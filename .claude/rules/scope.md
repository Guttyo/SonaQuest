# スコープ（MVP）

提出版の完成形と区分（A：提出に必須、B：追加、C：将来構想、D：よりよい到達点）は docs/PRD.md「提出版の完成形」と ADR-0031。下の「作るもの」は A の中身にあたる。

## 作るもの
- スマートフォンとデスクトップPCのウェブブラウザで使えるWebアプリ（最低限、スマホ幅への対応は必須。2026-11-04 オーナー、ADR-0031）。モードは1つ。薬の中身（薬があるか・名前・量・病名・ほかの薬・飲めているかなど）は**架空の内容で**答え、情報の在りか・ほかの伝え方・薬を知っている人・記録の新しさは本人のこととして振り返って答える（ADR-0022 の案B）。薬の名前・量は聞くが、正しいかは判定せず、本人が言ったこととして結果画面に原文で表示する（ADR-0009、ADR-0021）
  - 「モードは1つ」は訓練の役割のこと（患者の立場で答える）。2D／3D は同じ訓練の見せ方の違いで、別の訓練モードではない（ADR-0031）。2D（文字で答える）と 3D（パペットと音声で会話する）はどちらも必須で、利用者が選ぶ
- シナリオ：発災翌日の避難所の救護所
- 利用者の回答は最大10回（前半最大5回、後半最大5回。2026-11-04 オーナー決定、Issue #41、ADR-0019）。目安は約5〜10分（時間で強制終了しない。2026-11-04 オーナー決定、Issue #41。もとは約3分）
- Claude が利用者に質問し、回答を受け付ける。関係のない話には、受け止めてから本来の質問に答えるよう質問し直す。Claude に任せる範囲（言い回しだけか、聞く項目まで任せるか）は ADR-0025 で決める
  - オーナーが判断した点：Claude に任せる範囲（ADR-0025 の A・B）
  - → オーナー決定（2026-11-03、チャット）：A。聞く項目と順番は固定し、Claude は言い回しと、受け止め・質問し直しの文を作る（ADR-0025）。
- 音声で会話できるようにし、文字入力もできる。音声認識はブラウザ標準（Web Speech API）、音声合成は ElevenLabs（Workers 経由、キーは secrets）。認識した文は画面に出し、利用者が直せるようにする（ADR-0010）。ElevenLabs が使えないときはブラウザの読み上げに切り替え、音声認識が使えないブラウザでは文字入力で最後まで進める（ADR-0004、ADR-0005）
  - 音声は 3D の対話モードで使う。2D は文字で答える（2026-11-04 オーナー決定、ADR-0031）
- 確認する5観点
  1. 情報がどこにあるか
  2. その情報源が使えないときの代わりの手段
  3. 今の服用状況と、記録が最新か
  4. 記録に載っていない可能性のある情報
  5. 本人が説明できないときに代わりに伝えられる人
- 回答に応じた想定外の出来事を1回起こす（固定の6候補からルールで選ぶ）
- 結果画面：5観点それぞれの3段階の判定（確認できた／未確認と気づいた／確認していない）、利用者の回答（原文のまま）
- 準備行動を1つと、いつやるかを選んで終了
- いつでも訓練をやめられるボタン
- 外部音声サービスが無くても訓練を最後まで終えられる（ElevenLabs は使うが必須にしない）
- ログインなし、DBなし、会話を永続保存しない
- API失敗時は固定の質問で最後まで終えられる
- 使いやすいUIと2Dキャラクター（3Dパペットの2D版の姿）、お薬手帳・お薬の説明書・スマートフォンなどのイラスト、情報源や選択肢を文字と図の両方で示す表示（ADR-0031）
- 振り返りで、準備行動との関係が分かる形で公的資料へのリンクを示す。確認済みの出典だけを、確認日とともに出す（ADR-0031）
- 3Dパペットの音声対話モード（Issue #37）と、2D／3D のモード選択。3D は押して選べる選択肢にする（「Coming soon」と表示するのは C-01 だけ。PRD の A-14、ADR-0036）。WebGL が使えないときなどは 2D で続ける（ADR-0031）

## 追加するもの（B。A が完成してから）
- 出来事をグラフィカルに示すイベントUI、訓練の状況や変化が伝わる演出、BGM（ADR-0031）
- 地域本部の医薬品ボード（架空データのデモ。画面の題は「SonaQuest」。架空データだけで、Claude・API・保存を使わない。訓練の流れの外の画面）と、振り返りの「救護所に渡す記録の形」（回答を原文のまま項目に並べるだけ。要約しない）（B-04・B-05、ADR-0042、2026-11-05 オーナー決定「凍結の前に入れる」）。災害時の問診モード（実際の患者・要約・保存）は作らず、はじめにのボードのボタンの下の説明の文だけ（押せるものにしない。C-05、Issue #101）。ボードのデモ（救護所ごとの一覧、架空の問診の入力、デモ時計で在庫と需要が動く）はブラウザのメモリだけで、保存・送信・ログ出力をしない。架空の氏名はボードのデモだけで使い、訓練には入れない（B-06、ADR-0043、2026-11-05 オーナー決定）。ボードの地図は、架空の町の模式図を SVG で描いたものだけ（Issue #105、ADR-0042 の追記。外部の地図タイルや画像は使わない）。デモの中の発注の提案の承認・却下は作った（架空データの中で、ボードの状態（本部の在庫の引当、搬送、受領）が変わるだけ。承認・却下は人が押し、HQ でログインした人だけができる。ADR-0043 の追記（Issue #107）、ADR-0050 の追記（Issue #169））。ボードの実データの入力・保存・送信、処方の連携、実際の発注・配送の確定、外部の地図を使う表示は作らない（将来構想。ADR-0042 の追記）
- ボードの掲示板チャット（B-07、Issue #121、ADR-0047）：上の「ボードは Claude・API を使わない」の例外。2026-11-06 オーナー決定（チャット）で、本部と救護所A〜Dの役を Managed Agents のエージェントが演じ、Claude に作らせるのは薬剤以外の連絡文だけにする（薬の名前・量・病名・需要の数は作らせない）。エージェントに渡すのはボードの件数と時刻だけ。架空の書き込みは Anthropic 側のセッションに残る（privacy.md の例外）。到着の知らせをチャットに流すことは別の Issue
- ボードのデモ用ログインと救護所ごとの権限、カルテの確認状態、アクセス記録（B-09、Issue #141、ADR-0050。凍結の前の例外として 2026-11-06 オーナー指示。「凍結の前の例外」の呼び方は 2026-11-06 オーナー決定、チャット、Issue #188）：上の「ボードは Claude・API を使わない」の2つ目の例外。Worker（`/api/board/authorize`）へ送るのは、ログイン中の救護所・書き込み先の救護所・出来事の種類の3つだけで、カルテの中身・氏名・担当者名は送らない。ログイン・アクセス記録はメモリだけで保存しない。デモ用で偽装は簡単。本部（HQ）でもログインでき、HQ は全体を見て、発注の提案の承認・却下だけができる。救護所のカルテは編集できない（ADR-0050 の追記、Issue #169、2026-11-06 オーナー決定）。カルテの抽出型の要約と監査（B-10、Issue #142・#148、ADR-0052・ADR-0053。privacy.md・safety.md の例外）と、HQ のデザインの見直し（B-11、Issue #143、ADR-0055）も同じ凍結の前の例外で、これ以外は足さない（下の C-05 の文字起こしは、2026-11-06・11-07 のオーナー決定で足した例外。ADR-0061）
- HQ のカルテ画面の聞き取りの文字起こし（災害時の問診モード C-05 の一部、Issue #202、ADR-0061。2026-11-06・11-07 オーナー決定、チャット）：話すのは架空の患者で、オーナーが演じる見本。実際の患者は扱わない。本部の「記録（カルテ）」のタブで、HQ でログインしたときだけ出す。音声認識はブラウザ標準（3D と同じ部品）で、マイクの前に、ブラウザによって音声が事業者に送られることと、架空の内容だけを話し実在の人の情報を話さないことを出す。認識した文は直せる欄に足すだけで、メモリだけに持ち、保存・ログ出力をしない。カルテには書き込まない。音声認識が無いブラウザでは文字入力にする。要約は足した（2026-11-07 オーナー決定、チャット、「要約も進める」）：B-10 と同じ抽出型で、コードでの確認（`codeCheck.ts`）を通し、監査役には回さない。確かめの欄に印を付けて「要約を作る」を押したときだけ、文字起こしを Worker 経由で Claude に送る（privacy.md・safety.md の例外）。それ以外では Claude に送らない
- ボードのデモの架空の患者 100 人の到着（B-08、ADR-0048、2026-11-06 オーナー決定）：架空の患者（架空の氏名・性別・年齢・服薬・けが）が種付きの乱数とルールで救護所に到着し、服薬の品目の在庫を 3 日分ずつ減らす。Claude・API・保存・送信・ログ出力を使わない。けがの重さ・緊急度・処置は判断しない
- B が未完成でも、A の訓練を最後まで使える状態を保つ
- 受入条件は docs/PRD.md「提出版の完成形」。BGM と動きは、消音、読み上げとの両立、動きを減らす設定、中断の画面で止めることを含める

## 作らないもの
- 被災者を演じるモード、薬を当てるモード、複数の訓練モード（2D／3D の見せ方の選択は除く）
- 薬剤師・医師の立場から患者の服薬情報を確かめる訓練（C。将来構想。「Coming soon／将来構想・提供時期未定」の表示だけで、押して始められるものにしない。ADR-0031）
- 薬剤情報の入力・管理・保存、お薬手帳の代替機能
- アカウント、履歴、共有、分析用の会話ログ
- 公的制度の自由生成による説明（確認済みの固定文と出典のみ）

範囲外の依頼が来たら、理由を添えて断り、必要ならADR案として `docs/decisions.md` に書いてオーナーに諮る。
