# スコープ（MVP）

## 作るもの
- モバイル向けWebアプリ。モードは1つ。薬の中身（薬があるか・名前・量・病名・ほかの薬・飲めているかなど）は**架空の内容で**答え、情報の在りか・ほかの伝え方・薬を知っている人・記録の新しさは本人のこととして振り返って答える（ADR-0022 の案B）。薬の名前・量は聞くが、正しいかは判定せず、本人が言ったこととして結果画面に原文で表示する（ADR-0009、ADR-0021）
- シナリオ：発災翌日の避難所の救護所
- 利用者の回答は最大10回（前半最大5回、後半最大5回。2026-11-04 オーナー決定、Issue #41、ADR-0019）。目安3分（時間で強制終了しない）
- Claude が利用者に質問し、回答を受け付ける。関係のない話には、受け止めてから本来の質問に答えるよう質問し直す。Claude に任せる範囲（言い回しだけか、聞く項目まで任せるか）は ADR-0025 で決める
  - オーナーが判断した点：Claude に任せる範囲（ADR-0025 の A・B）
  - → オーナー決定（2026-11-03、チャット）：A。聞く項目と順番は固定し、Claude は言い回しと、受け止め・質問し直しの文を作る（ADR-0025）。
- 音声で会話できるようにし、文字入力もできる。音声認識はブラウザ標準（Web Speech API）、音声合成は ElevenLabs（Workers 経由、キーは secrets）。認識した文は画面に出し、利用者が直せるようにする（ADR-0010）。ElevenLabs が使えないときはブラウザの読み上げに切り替え、音声認識が使えないブラウザでは文字入力で最後まで進める（ADR-0004、ADR-0005）
- 確認する5観点
  1. 情報がどこにあるか
  2. その情報源が使えないときの代わりの手段
  3. 今の服用状況と、記録が最新か
  4. 記録に載っていない可能性のある情報
  5. 本人が説明できないときに代わりに伝えられる人
- 回答に応じた想定外の出来事を1回起こす（固定の6候補からルールで選ぶ）
- 結果画面：5観点それぞれの3段階の判定（確認できた／未確認と気づいた／確認していない）、利用者の回答（原文のまま）
- 準備行動を1つと、いつやるかを選んで終了
- いつでも訓練をやめられるボタン
- 外部音声サービスが無くても訓練を最後まで終えられる（ElevenLabs は使うが必須にしない）
- ログインなし、DBなし、会話を永続保存しない
- API失敗時は固定の質問で最後まで終えられる

## 作らないもの
- 被災者を演じるモード、薬を当てるモード、複数モード
- 薬剤情報の入力・管理・保存、お薬手帳の代替機能
- アカウント、履歴、共有、分析用の会話ログ
- 公的制度の自由生成による説明（確認済みの固定文と出典のみ）

範囲外の依頼が来たら、理由を添えて断り、必要ならADR案として `docs/decisions.md` に書いてオーナーに諮る。
