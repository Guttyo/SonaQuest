### うまくいったこと
- Yorukusuをリポジトリ外に参照用としてクローンし、仕組みだけを読み取って新しく書き起こした。コード・Skill本文・hookは複製していない。
- 音声認識・音声合成・Claude API・Workersログ・自動メモリの公開情報を調べ、未確認の点を分けてADRに残した。

### つまずいたことと直し方
- 作業環境にPython、Node.js、jqが無かった。hookを書くのにGit同梱のperlで代用し始めたが、オーナーから「環境が無いから自分で解決、は禁止。提案して」と指摘を受けた。perl版を消し、オーナーが入れるPythonで書き直した。以後、環境が足りないときは選択肢と推奨を示して提案する（CLAUDE.mdに明記）。
- hookを有効にする `.claude/settings.json` を、Python導入前に置くと全操作が止まる（Pythonが無いと止める設計のため）。Python導入後に置く順にした。
- 秘密情報の検出パターンで、`ANTHROPIC_API_KEY=` の後の改行をまたいで次の行の変数名を値と誤認する恐れに気づき、空白の照合を `[ \t]*` に限った。

### 捨てた案と理由
- hookをbash+jqで書く（jqが標準で入っていない環境が多い）。
- hookが判定できないとき（Pythonが無いなど）に通す設計（検査されないまま秘密情報がコミットされうる）。

### うまくいったこと

### つまずいたことと直し方
- Pythonを入れた後も、Claudeアプリのウィンドウを開き直すだけでは古いPATHのままだった。タスクトレイから完全に終了して起動し直すと見えるようになった。
- `git check-ignore .dev.vars` を他のコマンドと `&&` でつなぐと、hookが安全側に倒れて止めた。秘密ファイル名を含むコマンドは単独で実行する。
- 初回コミットで、メッセージに「TODO-OWNER」とCo-Authored-By行の `>` が入っていたため、マーカー保護hookがファイルの書き換えと誤認して止めた。単独の `git commit` はこの判定から外し（マーカーの削除はコミット前フックが見る）、`git commit && sed -i ...` のようにつないだ場合は引き続き止めることを試験に足した。

## 2026-11-02 Phase 0（外部監査の反映、GitHub運用、TODO-OWNER 1〜6）

### うまくいったこと
- 外部監査の指摘（緊急検出を過信しない、薬の名前を集めない、hookを境界とみなさない、出力のサーバー側検証、保存と外部送信の区別）を ADR-0007・0009・0011・0014〜0017 に反映した。
- オーナーが決めたTODO-OWNER 1〜6を、マーカーを残したまま横に書き足した。解除はオーナーが行う。
- GitHub運用（Issue → ブランチ → PR → 承認後のマージ）を `.claude/rules/github.md` にまとめ、main の保護を hook（`guard_github.py`）とgitのフック（pre-commit、pre-merge-commit）で補った。試験は63/63 PASS。

### つまずいたことと直し方
- macOSのリポジトリのパスに実名のユーザー名が含まれていた。オーナーに確認し、`~` 始まりで書いた。
- ADRの追記をheredocで行ったところ、本文にあったオーナー承認用の環境変数の名前にhookが反応して止めた。本文の追記はEditツールで行う。
- 単独開発ではGitHubで自分のPRを承認できないので、レビュー必須ではなく PR必須・CI必須・オーナーのチャットでの承認 の組み合わせにした。

### 捨てた案と理由
- 想定外の出来事をClaudeに選ばせる（比較実験の条件がそろわない。ルールで十分）。
- 5観点を二値で判定する（「わからないと気づけた」が埋もれる）。
