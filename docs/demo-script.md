## Cowork 向けの撮影の手順（2026-11-06）

Cowork（Claude がアプリを操作する）に渡す手順。目的は「操作の記録」ではなく「魅力が伝わる動き」なので、**1画面1判断、押す前に1拍、押した後に2拍**を守る。ナレーションは後から当てるので、画面の変化が止まってから次へ進む。

### 準備
- **録るのは再デプロイ後の公開 URL**（審査員が触る画面と同じもの）。手元で撮るときは `npm --prefix web run dev`（5173）と `dev:worker`（Claude と ElevenLabs）を起こす。Workers が無いと固定の質問で進み、振り返りの判定は「判定できませんでした」になる。
- 声の ID：撮影の前に、アプリ用の声の ID を本人の声から既製の声に替えておく（上の「声の割り当て」。オーナーの操作）。
- 画面の大きさ（2種類）：
  - 訓練（S1〜S9）：**幅 390px・高さ 844px** 相当のスマホ幅。Remotion 側でスマホの枠に入れて横長の画面に置く。
  - ボード（S10〜S12）：**1920×1080**（幅 1280px 以上）。
- 録画の設定：30fps。マウスカーソルは映さない（見せ方の提案 A。2026-11-07 にオーナーが提案をすべて採った）。押した所には Remotion で小さな波紋を後から足すので、押した時刻が分かるように操作の記録を残す。録画は 3 倍の解像度で撮る（寄ってもぼやけないように）。画面の音（アプリの声）も録る（S2 の1問目と S6 の立て直しの問いで使う。物語の構成では、ソナの問いをアプリの声で聞かせるため）。

### 調べたことの要点（2026-11-07 時点）
- **生成だけでは質が上がらない**。Claude Code から動画を組む道具は増えた（Remotion の公式の Agent Skills `remotion-dev/skills`、HeyGen の HyperFrames は HTML から MP4 を作り Claude Code の Skill で動かせる）。どちらも作り方の型を教えるもので、何を見せるか（物語・素材・間）は人が決める。
- **受賞者の教訓**：Built with Opus 4.7 の受賞者の1人は、Claude と HyperFrames で動画を作り、3分の動画は思ったより時間がかかる、次は最後の1日を動画だけに使う、と書いている。ほかの受賞作の記事に、動画の作り方の記述は無かった。
- **ハッカソンの動画の定番**：冒頭の数秒で「何を、誰のために」を言う。主役は動く製品で、コードは見せない。凝った編集より分かりやすい物語。アップロードには時間がかかるので早めに上げる。
- **画面の録画**：押した場所に寄るズームと、なめらかなカーソルが今の主流（Screen Studio が代表。macOS だけ）。指す・止まる・寄る、を分け、寄った後に一呼吸おく。
- **文字の動き**：画面の文字を動かして見せる表現が、2026年に最も多く挙げられている。音を消して見る人が多いことが理由。派手な効果より、意味に沿った動きが好まれる。
- **ElevenLabs の v4**：SSML の `<break>` は効かない。間は句読点・「…」・原稿の区切りで作る。日本語の間の取り方の資料は見つからなかった（試して確かめる）。
- 出典の多くは道具の会社のブログなので、傾向として読む。出典は下の一覧。
