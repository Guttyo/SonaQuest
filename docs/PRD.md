# PRD：SonaQuest（ソナクエスト）

## コンセプト：お薬の避難訓練
> もしもの時、自分の薬のことを伝えられますか？

SonaQuestは、災害時に普段の情報源が使えなくなっても、服薬情報を医療者に伝える準備ができているかを確かめる、約5〜10分の対話型の防災訓練です。

単なるチェックリストではありません。利用者が頼っている情報源を訓練の途中で1つ使えなくし、残った手段でどう伝え直すかを体験します。情報源を失うだけなら防災クイズですが、その後に伝え直すから「避難訓練」になります。

評価するのは薬の情報の正確さではなく、どの情報をどう伝えられたか、何が未確認だったかです。点数や合否は付けず、最後に具体的な準備行動を1つ選びます。

画面の中心は親しみやすい光のキャラクターです。救護所の聞き取りを、医療者向けの問診画面ではなく、一般の人が気軽に参加できる体験として表します（ADR-0020）。

## 課題
災害時、普段頼っているお薬手帳やスマートフォンが手元にない・使えない場面で、自分の服薬情報を救護所で伝えられない人がいる。多くの人はその場面を一度も想像したことがない。

## 対象
常用薬のある一般の成人。医療者向けではない。

## 目的
- 最終目標：普段の情報源が使えないときでも、自分の服薬情報を周囲に伝えられる状態に近づくこと。
- SonaQuest の役割：伝える準備を**振り返り、復習してしっかり覚える**きっかけを与えること（ADR-0022）。
- 5観点・出来事・立て直しは、そのための手段。

約5〜10分の音声対話で、発災翌日の避難所の救護所を疑似体験し、次の2つに気づいてもらう。
- 普段の情報源が使えないときの代わりの手段
- まだ確認できていないこと

薬の正誤を判断することは目的にしない。薬の名前を言えるかも評価しない（ADR-0009）。薬の名前・量・病名・何の薬かは、実際の聞き取りに合わせて質問してよいが、答えは原文のまま表示するだけで、判定も記録もしない（ADR-0021）。

### 答える範囲（ADR-0022 案B）
- 薬の中身（薬があるか・名前・量・病名・ほかの薬・市販薬・アレルギー・副作用・飲めているか）は、架空の内容で答える（ADR-0009）。
- 情報の在りか、ほかの伝え方、薬を知っている人（続柄と、連絡の手段の種類。連絡の手段は画面の選択肢で補う（Issue #110）。人の名前や電話番号、薬の中身は書かない）、記録が新しいかは、本人のこととして振り返って答える。
- 回答欄の案内は、質問ごとに「あなた自身のこと」「架空の内容で」「両方」を分けて示す（`web/src/flow/content.ts`）。

### 思い出せないとき（ADR-0022）
- 薬の名前・量・病名の候補や「〜ではないですか」は出さない。
- 振り返りで、「今ここで、実際のお薬手帳や薬の袋を確認しましょう」「今回のように、定期的にお薬の避難訓練をやって復習しておくとよいですね」と固定文で伝える（文面は `web/src/flow/content.ts` の下書き。オーナー確認待ち）。確認した内容の入力は求めない。

## 体験の核（ADR-0019）
訓練の中心は、頼っている情報源を1つ失った後、残った手段で伝え直す体験。核は次の4つの流れで、下の「体験の6段階」はこれを手順に分けたもの。

1. **伝える**：救護所で、普段の薬について聞かれ、どう伝えるかを答える
2. **頼っている手段が使えなくなる**：本人が確かめた一番の情報源が、出来事で使えなくなる（ADR-0016）。例「スマホの電池が切れてしまいました」
3. **立て直す**：残った手段で、もう一度伝えようとする。例「では、ほかにどうやって伝えられますか？」
4. **気づきと準備**：手薄なところを振り返り、次の準備を1つ決める

立て直しで伝え直せなくても失敗ではない。「伝えられない」と気づいたことを、準備行動につなげる。

### ③ 確認（本人による情報源の確認）
- ②の回答から、一番頼りにしている情報源を、出来事の6候補（ADR-0016）の分類のどれかとして初期選択にする。本人がタップでそのまま確かめるか、別のものを選び直す。
- 本人が確かめていない情報源を、出来事で失わせない。本人が実際には頼っていない情報源を使えなくすると、立て直しの体験にならないため。
- タップの操作で、自由に答える回答の回数には数えない。回答の枠（最大10回）を、訓練の本体に使うため。
- 初期選択の決め方（語の照合、Claudeの構造化出力のどちらを使うか）は実装時にADRで決める。どちらでも、出来事を決めるのは本人が確かめた分類とルールで、Claudeには選ばせない（ADR-0016）。初期選択が決められないときやAPI失敗時は、初期選択なしで本人に選んでもらう。
- 本人が選ばなかったとき（「わからない」を選んだ、選ばずに進んだ）は、「どれにも当てはまらない」と同じく「係の人が交代する」出来事へ進む。選べなかったことで訓練を止めない。
  - → オーナー指示（2026-11-03、チャット）：情報源を本人が選択しなかった場合は、既存の「係の人が交代する」出来事へ進める。

### 出来事で使えなくなるもの
出来事は「情報源の種類」ではなく「何が使えなくなったか」で定める。立て直しの判定（観点②）は、この表の「使えなくなるもの」に頼らない手段を挙げたかで見る。③確認の選択肢にも、違いが分かる説明を添える。

| ③で確かめた情報源（選択肢の説明） | 出来事 | 使えなくなるもの | まだ使えるものの例 |
|---|---|---|---|
| スマートフォン（スマホに保存した写真・メモ・アプリの記録） | 電池が切れた | スマホ本体。端末内の写真・メモ・アプリ、スマホでの電話や通信のすべて | 紙のお薬手帳や写し、財布のメモ、薬の袋や説明書、家族、かかりつけ先 |
| アプリ・マイナポータル（インターネットにつないで見るもの） | 通信がつながらない | インターネットと電話。マイナポータルなどネット上のサービス、電話・メールでの問い合わせ | スマホに保存済みの写真・メモ・アプリ内の記録、紙の記録、そばにいる家族 |
| お薬手帳 | 手帳が自宅にあり、今は戻れない | 紙のお薬手帳そのもの | 手帳を撮った写真、写し、薬の袋や説明書、家族、かかりつけ先 |
| 家族 | 家族と連絡がつかない | その家族に聞くこと | 手元の記録、ほかに知っている人、かかりつけ先 |
| 薬局・病院 | かかりつけ先も被災して連絡がつかない | かかりつけ先への問い合わせ | 手元の記録、家族 |
| どれにも当てはまらない／選ばなかった | 係の人が交代し、最初から説明し直す | なし | — |

- 電池切れと通信の途絶は別のもの。電池切れでは端末内の情報も見られないが、通信の途絶では、スマホに保存してある情報は見られる。
- お薬手帳アプリのように、端末内に記録があるかどうかがアプリによって違うものは、本人の説明に従う。「アプリに保存してあるので、通信がなくても見られる」と説明したら、通信の途絶の後の手段として数える。その説明が正しいかは判定しない（ADR-0017）。
- 係の交代では使えなくなるものがない。後半の最初の問いは交代用の固定文（例「係が代わりました。もう一度、どうやって伝えるか教えてもらえますか？」）にする。観点②は、前半と後半の回答を通じて、別の手段を挙げたかで見る（Claude Codeの下書き。ADR-0019のマーカーの範囲）。
  - **確認できた**：前半で挙げた情報源とは別の、具体的な手段を挙げた（前半・後半のどちらで挙げてもよい）
  - **未確認と気づいた**：「ほかの手段はわからない」など、代わりの手段を知らないと本人が言葉にした
  - **確認していない**：前半と同じ情報源を繰り返しただけ、または伝える手段に触れなかった
- → オーナー指示（2026-11-03、チャット）：「スマホの電池切れ」と「通信がつながらない」を区別し、代わりの手段の判定にもその違いを反映する。

## 体験の流れ（MVP）
1. 初回画面：訓練の説明、架空の場面であること、入力内容がAnthropic（Claude API）へ送られること、氏名・住所・電話番号・実際の患者情報は入力しないこと、架空の薬の情報で練習すること（本人やほかの人の実際の服薬情報は入力しない。ADR-0009 2026-11-03 オーナー決定）、在りか・ほかの伝え方・薬を知っている人は本人のこととして振り返って答えること（ADR-0022）、薬の正確さや治療の適否は判定しないこと、外部APIの保持方針（自アプリと外部事業者を分けて表示）、体調に異変があるときは訓練をやめること（利用開始の文面は ADR-0009、体調の異変・自傷のときの案内は ADR-0011）
2. 場面の導入：発災翌日、避難所の救護所。聞き取り係の光のキャラクター（ADR-0020）が話しかける
3. 対話：利用者の回答は最大10回（前半と後半の配分は「回答の配分」）。音声優先、文字入力も可。曖昧な回答には聞き返す。画面には常に「訓練をやめる」ボタンを置く（ADR-0011）
4. 想定外の出来事：回答に応じて1回。前半の後に、本人がタップで確かめた一番の情報源（「③ 確認」）から、固定の候補をルールで選ぶ（ADR-0016）。出来事の後は、固定の立て直しの問いから対話の後半に入る（ADR-0019）
   - → オーナー決定（2026-11-02、チャット）：推奨Aを採用。回答で一番頼りにしている情報源に応じて、次の固定の6候補から選ぶ。Claudeには選ばせない。
     | 一番頼りにしている情報源 | 出来事 |
     |---|---|
     | スマートフォン | 電池が切れた |
     | お薬手帳 | 手帳が自宅にあり、今は戻れない |
     | 家族 | 家族と連絡がつかない |
     | 薬局・病院 | かかりつけ先も被災して連絡がつかない |
     | アプリ・マイナポータル | 通信がつながらない |
     | どれにも当てはまらない | 係の人が交代し、最初から説明し直す |
5. 結果画面：5観点それぞれの3段階の判定（ADR-0017）と、利用者の回答（原文のまま。端末内に保持した入力から表示し、Claudeの応答から復元しない）。「確認できた」は説明できたという意味で、内容の正確さを保証しないことを画面に書く。回答は出来事の前と後に分け、その間に何が使えなくなったか（出来事）を示す。「確認していない」「未確認と気づいた」の観点を「手薄なところ」として示し、点数・順位・合否は出さない（「評価の方針」）。思い出せなかったことは、今ここで実際のお薬手帳や薬の袋で確かめるよう固定文で促す（ADR-0022「思い出せないとき」）。準備行動や公的な仕組みに触れる固定文には、出典と確認日を添える（docs/references.md）。画面の並びは、受け止め → 手薄なところ（判定が無い回は出さない）→ 出来事と立て直しの回答（使えなくなったものを絵と文字で示し、立て直しの問いへの回答を原文で出す）→ 5つの観点の判定（「確認できた」の意味の注記を直下に）→ 回答の原文（出来事の前後に分ける）→ 今ここで確かめましょう → 次の準備（Issue #49）
6. 準備行動を1つ選び、いつやるかを選んで終了
   - → オーナー決定（2026-11-02、チャット）：推奨案を採用。「確認していない」「未確認と気づいた」だった観点に関係する行動を上に並べる。1つ選び、具体的な実行の予定を示せるようにする（例：今日中／今週中／次の休み）。
     - お薬手帳（または写し）を非常持ち出し袋に入れる
     - お薬手帳のページや薬の説明書をスマホで撮り、紙にも控える
     - 飲んでいる薬のメモを財布に入れる
     - 家族に、自分の薬の情報がどこにあるかを伝えておく
     - かかりつけ薬局の連絡先を控える
     - マイナポータル等で自分の薬の情報が見られるか確かめておく

## 確認する5観点
1. 情報がどこにあるか
2. その情報源が使えないときの代わりの手段
3. 今の服用状況と、記録が最新か
4. 記録に載っていない可能性のある情報
5. 本人が説明できないときに代わりに伝えられる人

各観点の「確認できた」の基準：
- → オーナー決定（2026-11-02、チャット）：二値でなく3段階にする（ADR-0017）。「知らない」「確認できない」も大事な気づきとして扱う。以下はClaude Codeの下書きで、オーナーが確認する。
  - 「確認できた」は発言内容を確認できたという意味で、医学的な正確さの保証ではない（ADR-0017）。
  - 共通：**確認できた**＝具体的な情報源や手段を説明できた／**未確認と気づいた**＝足りない情報があることを本人が言葉にした（「わからない」「確かめていない」など）／**確認していない**＝その観点に触れていない
  | 観点 | 確認できた の例 | 未確認と気づいた の例 |
  |---|---|---|
  | ① 情報の在りか | 具体的な情報源を1つ以上挙げた（お薬手帳、スマホのアプリ、薬の袋や説明書、マイナポータル、かかりつけ薬局、家族など） | 「どこにあるかわからない」 |
  | ② 代わりの手段 | ①が使えない場合の別の手段を1つ以上挙げた | 「手帳が無いと伝えられない」 |
  | ③ 今の服用状況と記録の新しさ | 今使っている薬に触れ、さらに「最近変わったか」か「記録が最新か」のどちらかに触れた（「変わっていない」も含む。2026-11-05 オーナー決定、ADR-0046。旧：「今飲めているか・最近変わったか」と「記録が最新か」の両方） | 「最近薬が変わったが、手帳に載っているかわからない」 |
  | ④ 記録に無い情報 | 市販薬・サプリ、他の医療機関の薬、アレルギーや副作用の経験、最近やめた薬のどれかに触れた | 「ほかに何を伝えればいいかわからない」 |
  | ⑤ 代わりに伝えられる人 | 具体的な人を挙げ、その人への連絡手段か、その人が知っている内容にも触れた | 「代わりに伝えられる人がいない」 |

立て直しの回答の扱い（ADR-0019）：
- [TODO-OWNER: 立て直しの回答と観点②の関係（Claude Codeの下書き）]
- → オーナー指示（2026-11-03、チャット）：出来事で使えなくなった情報源に依存しない、具体的な別の手段を挙げられたら、観点②の「確認できた」の根拠にする。本人が代わりの手段を知らないと認識したら「未確認と気づいた」とする。医学的な正誤は判定しない。
- → オーナー決定（2026-11-03、チャット、2回目）：立て直しの判定を採用。
- 観点②（代わりの手段）は、主に出来事の後の回答で確かめる。
  - **確認できた**：使えなくなった情報源に依存しない、具体的な別の手段を挙げた（例：スマホが使えないときに、紙のお薬手帳や財布のメモ、かかりつけ薬局への問い合わせを挙げた）
  - **未確認と気づいた**：「それが無いと伝えられない」「ほかに思いつかない」など、代わりの手段を知らないと本人が言葉にした
  - **確認していない**：出来事の後に、伝える手段に触れなかった
- 使えなくなった情報源に依存する手段は、立て直しの回答として数えない（例：スマホの電池切れの後の「スマホに保存した写真」。出来事の前に挙げていた手段でも、出来事で使えなくなったものは同じ）。何が使えなくなるかは「出来事で使えなくなるもの」の表に従う（例：通信の途絶の後の「スマホに保存した写真」は数える）。
- 判定するのは、伝える手段を挙げられたかどうかだけ。挙げた手段で実際に伝わるか、薬の正誤、治療の適否、医学的に十分かは判定しない。

## 評価の方針（ADR-0019）
- 点数、合計点、合否、順位、「5観点中いくつ」といった数で利用者を評価しない。結果画面に出すのは、観点ごとの3段階の判定と回答の原文だけ。
- 「確認していない」「未確認と気づいた」の観点は、失敗ではなく「手薄なところ」として示し、準備行動を選ぶ手がかりにする。
- 「成功の目安」の数値（達成率など）は、審査とふりかえりのために開発側が測るもので、利用者の画面には出さない。

## 聞き取り係のキャラクター（ADR-0020）

## 提出版の完成形（ADR-0031、Issue #44）
提出版で何ができれば「完成」かを、要件ID・区分・受入条件で定める。区分を決めた理由と過去の決定から変えたところは ADR-0031、要件ごとの状態（決定・実装・動作確認・安全確認）と証跡は `docs/STATUS.md`「提出版の要件と進捗」に書く。ここには状態を書かない。

### 完成体験
- 患者の立場で、「災害時に自分の服薬情報をどう伝えるか」を練習する。
- 体験の核は変えない：伝える → 頼っている情報源が使えなくなる → 別の手段で立て直す → 振り返りと準備行動につなげる（上の「体験の核」、ADR-0019）。
- 文字ばかりにせず、イラストや図でも内容が分かり、参加しやすい体験にする。
- 患者向けに 2D と 3D のモードを用意し、利用者が選べるようにする。2D は 3D が動かないときの代用品だけでなく、正式な選択肢として残す。
- 3D は、パペットと音声（認識と読み上げ）で会話する、よりインタラクティブな対話のモード。2D は文字で答えるモード（2026-11-04 オーナー決定、ADR-0031）。どちらも提出に必須。
- 2D／3D は同じ訓練の見せ方の違いで、訓練の役割（患者の立場で答える）は1つのまま（`.claude/rules/scope.md`）。

### 完了条件（提出版の基本）
A の各項目が、次の3つをすべて満たしたら、提出版の基本の完成とする。
1. 実装され、main に取り込まれている
2. 動作確認が済み、対象コミット・日付・環境・結果が `docs/STATUS.md` に記録されている
3. 必要な安全確認が済み、未解決事項の扱い（直す・公開前に確かめる・受け入れる理由）が明確になっている

- 単体試験だけでなく、開始から振り返り・公的資料への導線までの通し操作を確かめる（A-12）。
- デプロイ（D-01）は基本の完成条件に含めない。
- 進捗は A の要件のうち3条件を満たした数で示す。Phase の数では示さない。C は数えない。

| B-06 | ボードのデモ（救護所ごとの一覧、架空の問診の入力、デモ時計） | 一覧は救護所ごとで、救護所の行（人員と薬の不足）→ 品目の行の2タップで連絡先・入荷・経路に届く。架空の問診（架空の氏名・訓練と同じ6項目・人が選ぶ「医師の処方」）を加えると、その救護所の記録に架空の氏名と番号で加わり、今日の患者が増え、処方の数量だけ現地の在庫が減り、足りない分は未交付として需要に載る。デモ時計を進めると出庫のペースで在庫が減り、到着見込みを過ぎた入荷・搬送が受領になって在庫が増え、搬送便・連絡員の時刻に紙の記録が本部に届く。自動進行・一時停止・手動進行・最初に戻すがあり、動きを減らす設定では自動で進めない。状態はブラウザのメモリだけで、保存・送信・ログ出力をせず、タブを閉じると消えることを画面に書く。架空の氏名はボードのデモだけで使い、訓練には入れない。薬の正誤・服薬・処方の判断をせず、文は入れたまま出す（ADR-0043、Issue #102）。発注の提案と承認（Issue #107）：未交付や目安より早く切れる見込みの品目について、必要な数量を在庫と未交付の算数だけで出し（内訳を画面に出す）、本部備蓄から出せる分と卸へ頼む分に分ける。本部の画面で人が承認すると本部の在庫を引き当て、搬送が入荷・搬送の一覧に引当済みで載り、時計で搬送中 → 受領になって現地の在庫が増える。却下は提案を消すだけ。薬の中身・代わりの薬・量の妥当性は判断しない（ADR-0043 の追記）。タブの下の「前回から変わったこと」の1行は、デモの記録の件数だけをルールで並べる（氏名・品目名・数量は入れない。Claude は使わない）。左のペインと救護所の詳細に「最終報告 N 時間前」を出す（記録の新しさ。閾値は作らない）。カルテ入力は在庫管理から切り分けた全画面の専用画面で行い、閲覧は記録タブのまま。カルテの処方の累計（人が入れた数量を足すだけ）を救護所の詳細に出し、発注の提案の内訳の根拠として示す（Issue #114） |
| B-07 | ボードの掲示板チャット（本部と救護所の DM と共通の欄。Managed Agents が役を演じる） | ボードの上部のタブ「連絡」に、左の欄（本部のすべての欄・共通の欄・救護所A〜Dの DM）と右の吹き出しを出す。開いたときは件数と時刻だけをルールで並べた固定の掲示で、エージェントを呼ばない。「エージェントの連絡を始める」を押すと、本部と救護所A〜Dの5役を Managed Agents のエージェントが演じ、薬剤以外の連絡（処方箋の用紙・物資・食糧・人員・通信・搬送）だけをやりとりする。だれがどの欄に書くかはルールで決める。人は欄を選んで本部として書き込め、その欄の相手が返事をする。エージェントに渡すのはボードの件数と架空の時刻とその欄の書き込みだけで、薬の品目名・数量・カルテの文・架空の氏名は渡さない。エージェントの文は Workers の検査（長さ、薬・病名・量・助言・診断・個人の情報、許していないカタカナ・英字の言葉）を通ったものだけを出し、通らなければその1件を固定の掲示に替える。Agent の ID が無い・失敗・支出の上限・回数制限のときは固定の掲示だけで画面が成り立ち、ボードのほかの機能は止まらない。始める前と入力欄の上に、架空の訓練用であることと、書いた内容が Anthropic の Managed Agents のセッションに送られ残ることを書く。画面の状態はブラウザのメモリだけ。公開する版のログに本文を出さない。幅375pxで横にはみ出さない（ADR-0047、Issue #121） |
