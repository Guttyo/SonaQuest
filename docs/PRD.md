# PRD：SonaQuest（ソナクエスト）

## コンセプト：お薬の避難訓練
> もしもの時、自分の薬のことを伝えられますか？

SonaQuestは、災害時に普段の情報源が使えなくなっても、服薬情報を医療者に伝える準備ができているかを確かめる、約3分の対話型の防災訓練です。

単なるチェックリストではありません。利用者が頼っている情報源を訓練の途中で1つ使えなくし、残った手段でどう伝え直すかを体験します。情報源を失うだけなら防災クイズですが、その後に伝え直すから「避難訓練」になります。

評価するのは薬の情報の正確さではなく、どの情報をどう伝えられたか、何が未確認だったかです。点数や合否は付けず、最後に具体的な準備行動を1つ選びます。

画面の中心は親しみやすい光のキャラクターです。救護所の聞き取りを、医療者向けの問診画面ではなく、一般の人が気軽に参加できる体験として表します（ADR-0020）。

## 課題
災害時、普段頼っているお薬手帳やスマートフォンが手元にない・使えない場面で、自分の服薬情報を救護所で伝えられない人がいる。多くの人はその場面を一度も想像したことがない。

## 対象
常用薬のある一般の成人。医療者向けではない。

## 目的
約3分の音声対話で、発災翌日の避難所の救護所を疑似体験し、次の2つに気づいてもらう。
- 普段の情報源が使えないときの代わりの手段
- まだ確認できていないこと

薬の正誤を判断することは目的にしない。薬の名前を言えるかも評価しない（ADR-0009）。

## 体験の核（ADR-0019）
訓練は次の4段階で進む。下の「体験の流れ」と「6画面の構成」は、この4段階を画面と手順に割り当てたもの。

| 段階 | 起きること | 例 |
|---|---|---|
| ① 伝える | 救護所で、普段の薬について聞かれ、どう伝えるかを答える | 「普段飲んでいる薬のこと、どうやって伝えますか？」 |
| ② 頼っている手段が使えなくなる | ①で一番頼りにしていた情報源が、出来事で使えなくなる（ADR-0016） | 「スマホの電池が切れてしまいました」 |
| ③ 立て直す | 残った手段で、もう一度伝えようとする | 「では、ほかにどうやって伝えられますか？」 |
| ④ 気づきと準備 | 伝えられたこと・未確認だったことを振り返り、次の準備を1つ決める | 結果画面と準備行動の選択 |

③で伝え直せなくても失敗ではない。「伝えられない」と気づいたことを、④で準備行動につなげる。

## 体験の流れ（MVP）
1. 初回画面：訓練の説明、架空の場面であること、入力内容がAnthropic（Claude API）へ送られること、氏名・住所・電話番号・実際の患者情報は入力しないこと、架空の薬の情報でも練習できること、薬の正確さや治療の適否は判定しないこと、外部APIの保持方針（自アプリと外部事業者を分けて表示）、体調に異変があるときは訓練をやめること（利用開始の文面は ADR-0009、体調の異変・自傷のときの案内は ADR-0011）
2. 場面の導入：発災翌日、避難所の救護所。聞き取り係の光のキャラクター（ADR-0020）が話しかける
3. 対話：利用者の回答は最大6回（前半と後半の配分は「回答の配分」）。音声優先、文字入力も可。曖昧な回答には聞き返す。画面には常に「訓練をやめる」ボタンを置く（ADR-0011）
4. 想定外の出来事：回答に応じて1回。固定の候補からルールで選ぶ（ADR-0016）。出来事の後は、固定の立て直しの問いから対話の後半に入る（ADR-0019）
   - → オーナー決定（2026-11-02、チャット）：推奨Aを採用。回答で一番頼りにしている情報源に応じて、次の固定の6候補から選ぶ。Claudeには選ばせない。
     | 一番頼りにしている情報源 | 出来事 |
     |---|---|
     | スマートフォン | 電池が切れた |
     | お薬手帳 | 手帳が自宅にあり、今は戻れない |
     | 家族 | 家族と連絡がつかない |
     | 薬局・病院 | かかりつけ先も被災して連絡がつかない |
     | アプリ・マイナポータル | 通信がつながらない |
     | どれにも当てはまらない | 係の人が交代し、最初から説明し直す |
5. 結果画面：5観点それぞれの3段階の判定（ADR-0017）と、利用者の回答（原文のまま。端末内に保持した入力から表示し、Claudeの応答から復元しない）。「確認できた」は説明できたという意味で、内容の正確さを保証しないことを画面に書く。回答は出来事の前と後に分け、その間に何が使えなくなったか（出来事）を示す。点数・合否は出さない（「評価の方針」）
6. 準備行動を1つ選び、いつやるかを選んで終了
   - → オーナー決定（2026-11-02、チャット）：推奨案を採用。「確認していない」「未確認と気づいた」だった観点に関係する行動を上に並べる。1つ選び、具体的な実行の予定を示せるようにする（例：今日中／今週中／次の休み）。
     - お薬手帳（または写し）を非常持ち出し袋に入れる
     - お薬手帳のページや薬の説明書をスマホで撮り、紙にも控える
     - 飲んでいる薬のメモを財布に入れる
     - 家族に、自分の薬の情報がどこにあるかを伝えておく
     - かかりつけ薬局の連絡先を控える
     - マイナポータル等で自分の薬の情報が見られるか確かめておく

## 確認する5観点
1. 情報がどこにあるか
2. その情報源が使えないときの代わりの手段
3. 今の服用状況と、記録が最新か
4. 記録に載っていない可能性のある情報
5. 本人が説明できないときに代わりに伝えられる人

各観点の「確認できた」の基準：
- → オーナー決定（2026-11-02、チャット）：二値でなく3段階にする（ADR-0017）。「知らない」「確認できない」も大事な気づきとして扱う。以下はClaude Codeの下書きで、オーナーが確認する。
  - 「確認できた」は発言内容を確認できたという意味で、医学的な正確さの保証ではない（ADR-0017）。
  - 共通：**確認できた**＝具体的な情報源や手段を説明できた／**未確認と気づいた**＝足りない情報があることを本人が言葉にした（「わからない」「確かめていない」など）／**確認していない**＝その観点に触れていない
  | 観点 | 確認できた の例 | 未確認と気づいた の例 |
  |---|---|---|
  | ① 情報の在りか | 具体的な情報源を1つ以上挙げた（お薬手帳、スマホのアプリ、薬の袋や説明書、マイナポータル、かかりつけ薬局、家族など） | 「どこにあるかわからない」 |
  | ② 代わりの手段 | ①が使えない場合の別の手段を1つ以上挙げた | 「手帳が無いと伝えられない」 |
  | ③ 今の服用状況と記録の新しさ | 「今飲めているか・最近変わったか」と「記録が最新か」の両方に触れた | 「最近薬が変わったが、手帳に載っているかわからない」 |
  | ④ 記録に無い情報 | 市販薬・サプリ、他の医療機関の薬、アレルギーや副作用の経験、最近やめた薬のどれかに触れた | 「ほかに何を伝えればいいかわからない」 |
  | ⑤ 代わりに伝えられる人 | 具体的な人を挙げ、その人への連絡手段か、その人が知っている内容にも触れた | 「代わりに伝えられる人がいない」 |

立て直しの回答の扱い（ADR-0019）：

- 観点②（代わりの手段）は、主に出来事の後の回答で確かめる。使えなくなった情報源以外の手段で伝えようとした → 確認できた。「それが無いと伝えられない」「ほかに思いつかない」と言葉にした → 未確認と気づいた。
- 出来事の前に挙げた手段であっても、出来事で使えなくなったものは、立て直しの回答としては数えない。
- 判定するのは、伝える手段を挙げられたかどうかだけ。挙げた手段で実際に伝わるか、医学的に十分かは判定しない。

## 評価の方針（ADR-0019）
- 点数、合計点、合否、順位、「5観点中いくつ」といった数で利用者を評価しない。結果画面に出すのは、観点ごとの3段階の判定と回答の原文だけ。
- 「確認していない」「未確認と気づいた」は失敗ではなく、準備行動を選ぶ手がかりとして示す。
- 「成功の目安」の数値（達成率など）は、審査とふりかえりのために開発側が測るもので、利用者の画面には出さない。

## 聞き取り係のキャラクター（ADR-0020）
- 役割：救護所の聞き取り係。利用者の話を聞き、聞き返し、場面を進める。医師・看護師・薬剤師ではなく、医療的な助言や判断はしない（`.claude/rules/safety.md`）。
- 見た目の方向性：ホワホワとした、やわらかい光の存在（「光の精霊」のような姿）。白衣・聴診器・ナースキャップなど医療者を連想させる記号は使わない。問診画面ではなく、気軽に参加できる訓練に見えることを優先する。
- 作り方：凝ったイラストや3Dは作らない。CSSやSVGの光の表現で、待機・聞いている・話している、程度の状態を見分けられれば足りる。外部素材を使う場合は利用条件を確認する（README のライセンスの方針）。
- 動きを減らす設定（`prefers-reduced-motion`）では、光の動きを止めるか弱める。状態は動きだけでなく文字でも示す。
- 緊急時の中断画面（ADR-0011）では、キャラクターの演出をやめ、固定の案内文を落ち着いた表示で出す。
- 出来事「どれにも当てはまらない」（係が交代）では、別の色の光に代わるなど、交代が分かる表示にする。

## Claudeの役割としないこと
`.claude/rules/safety.md` のとおり。想定外の出来事の選択はClaudeの役割から外した（ADR-0016）。

## 要件
- 目安3分。時間で強制終了しない
- ログインなし。会話を永続保存しない
- API失敗時も固定の質問で最後まで終えられる。それまでの回答と進行は失わない
- いつでも訓練をやめられる。症状の訴えらしい入力では中断し、固定の案内を出す（すべてを検出できるとは説明しない）
- iPhone Safariで動く
- 初期版では外部音声サービスを必須にしない

## 成功の目安（審査向けの測定は docs/evidence.md）
- 情報伝達の達成率：訓練の終わりに、5観点のうちどれを伝えられたか、未確認のことにどう気づいたか
- 立て直し：出来事の後に、残った手段で伝え直せたか、または伝えられないことに気づいたか
- 次の行動の明確さ：訓練の後に、具体的な準備行動と実行の予定を選べたか
- 禁止出力（薬剤・病名の推定、助言、診断）が試験で0件
