## 5. プロンプトで禁じること（safety.md、ADR-0021・0022）
次をシステムプロンプトに書き、出力の検証と試験（S1〜S15）で確かめる。足すもの・外すものがあれば書く。
- 薬の名前・量・病名の推定、候補の提示、「〜ではないですか」
- 薬の名前の修正、薬効の評価、正誤の判定、服薬の適否の判断、診断、緊急度の判断
- 備蓄量などの医学的な助言、公的制度の説明の生成
- 利用者の発言の要約・言い換え・創作
- 薬の名前を言えたかどうかで判定を変えること
- 思い出せないという回答に、候補で補うこと（「未確認と気づいた」とし、振り返りの固定文に任せる）
- 実際のお薬手帳や薬の袋で確かめた内容を、入力するよう求めること（ADR-0022）
- 人の名前・電話番号・住所などを尋ねること（薬を知っている人は続柄などで答えてもらう。ADR-0022）

## 9. 失敗・時間切れ・検証の失敗（ADR-0012・0015）
- 推奨：Claude の応答を一定時間（例：8秒）待ち、失敗・時間切れ・検証の失敗のどれでも、**その回の残りを固定の質問の進行に切り替える**。それまでの回答と進行は失わない。判定できなかった観点は「判定できませんでした」
- 応答が `refusal`（安全の判定で断られた）のときも同じ扱いにする。参照資料は、Opus 5.5・Sonnet 5.5 では応答を断られたときに別のモデルで答え直す設定（`fallbacks: "default"` と専用の beta ヘッダー）を勧めている。使うかを決める
- SDK は失敗時に自動で2回まで再試行する。待ち時間の合計が延びるので、再試行の回数も決める
- [TODO-OWNER: 待つ時間、再試行の回数、断られたときに別のモデルで答え直す設定を使うか]
- → オーナー決定（2026-11-04、チャット）：合計8秒待ち、SDK の自動の再試行はしない。断られた（`refusal`）ときも別のモデルで答え直さず、固定の進行に切り替える。

## 13. `/api/turn` の出力の形と、進め方の決まり（Issue #15、`docs/architecture.md`）
`docs/architecture.md` の案をもとに、許す値を決める。項目2〜8の選択で変わるところは、決まった後に合わせる。
- `emergency`：真偽値（補助。項目10）
- `viewpoints`：5観点それぞれ `confirmed` ／ `aware_unconfirmed` ／ `not_mentioned`（ADR-0017）。API失敗時は画面側で「判定できませんでした」
- `next.type`：`ask`（次の固定の質問）／ `clarify`（聞き返し）／ `redirect`（関係のない話を受け止めて本来の質問に戻す。項目3と #19）／ `finish`（後半を終える）
- `next.question_id`：実際の質問ID（`first_medicines`、`first_location`、`first_other`、`second_recovery`、`second_handover`、`second_recent`、`second_proxy`、`second_proxy_other`）だけ。`clarify`・`redirect` のときは、戻り先（いま聞いている質問）のIDを入れる。`finish` のときは `null`
- `next.text`：Claude が作った文（質問文、受け止めの一言、質問し直す文。項目3、ADR-0025）。長さの上限つきの文字列か `null`。Workers で長さ・禁止表現・利用者の発言の繰り返しを検査し、通らないときや `null` のときは `question_id` の固定文を出す（`clarify`・`redirect` 用の固定文も `question_id` ごとに用意する）
- `recall`：思い出せない回答だったか（真偽値。項目7）
- `source_guess`：③確認の初期選択の候補（項目6）。値は `"smartphone"` ／ `"online"` ／ `"notebook"` ／ `"family"` ／ `"clinic"` のどれか、または候補が無いときは JSON の `null`（キーは省略しない）。`"none"`（どれにも当てはまらない＝係の交代）は**返させない**。「どれにも当てはまらない」と係の交代は、本人のタップでだけ選ぶ（ADR-0016）。検証（ADR-0015）で、これ以外の値は拒否して初期選択なしにする
- 進め方の決まり：前半は最大3回・後半は最大3回（聞き返しも数える。ADR-0019）、③確認はタップで回数に数えない、後半の最初は必ず立て直しの問い、上限に達したら追加の質問をしない
- オーナーが判断した点：関係のない話を受け止めて質問し直したとき（`redirect`）を、回答の回数に数えるか
- → オーナー決定（2026-11-03、チャット）：数えない。質問し直しは1つの質問につき1回までにし、2回目はそのまま回答として受け取る（ADR-0025）。
