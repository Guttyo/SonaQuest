## 2. いちばん大事な論点
PRD「目的」「体験の核」、README、KEEP-THINKING 11-03 は「気づく」「伝える準備」で書かれ、「思い出す・振り返る」は未登場。意味は衝突しておらず、最終目標→役割→手段（5観点）の階層が書かれていないだけ。KEEP-THINKING 11-03 の整理を PRD に持ち上げれば足りる。

本当のずれは、「**自分の**準備を思い出す」体験と、`web/src/flow/content.ts` の `INTRO_POINTS`「架空の人になったつもりで」・全欄 `ANSWER_PLACEHOLDER`「架空の内容で」。架空の人の準備を振り返っても本人の復習にならず、ADR-0021「答えられるか自体が気づき」も成立しない（#12 論点1・3）。

整理の軸：思い出す対象は**5観点の準備**（在りか・代わりの手段・記録の新しさ・伝えられる人）であり、薬の名前ではない（ADR-0009/0021「言えたかは評価しない」）。#12 の A/B/C に「実名が入力欄に打たれるか」の軸を足して比べ、選ぶのはオーナー。

直し方は #12 の PR の中で ADR を1本（新規 Issue は不要）：役割「伝える準備を思い出し振り返るきっかけ」＋A/B/C 比較＋影響一覧。採用後に PRD「目的」冒頭3行（最終目標／役割／5観点は手段）、README「何をするアプリか」1文、evidence に**未検証**の主張1行。

新しく要る安全の線：「思い出せない」と答えた利用者に、Claude が候補・一般的な量・「〜ではないですか」を出さない。「思い出す」が推定に変わる唯一の経路。`.claude/rules/safety.md`「しないこと」か ADR-0021 追記に `TODO-OWNER マーカー` 付きで提案する。

語：公開文（README/PRD/UI/デモ）は「伝える準備を思い出す・振り返るきっかけ」＋3つの限定（正しさは確かめない／思い出せない＝気づき／ヒントは出さない）。「復習」「把握」「薬を思い出す」は採点・暗記の印象を与えるので避ける。「〜できるようになる」は効果として書かない。

## 4つの観点のレビュー（全文）

### 観点1：コンセプトとの一致（思い出すための振り返りのきっかけ）

#### 結論（優先順位）

1. **コンセプトの食い違いは Issue #12 の決着で解消する**。新しいIssueは要らない。「思い出せるように復習する」は、利用者が**自分のこと**を答える前提に立つ。ところが ADR-0009（2026-11-03決定）と `web/src/flow/content.ts`（`INTRO_POINTS`「架空の人になったつもりで」、全回答欄の `ANSWER_PLACEHOLDER`「架空の内容で答えてください」）は、すべてを架空で答えさせる。架空の人の準備を振り返っても、本人の復習にはならない。#12 の案Bを採用した時だけ、「復習のきっかけ」が文字どおり成立する。
2. **PRD「目的」に最終目標と役割を1段落足し、短い ADR-0022 を書く**（最小限の変更。下の「書き直す文書」）。
3. **復習の対象は「伝える準備（5観点）」であり「薬の名前」ではない**と、公開文で明示する（下の「安全上の注意」）。
4. 「繰り返せる復習」の機能追加はスコープ変更。凍結前には入れず、#16 roadmap に置く。

#### 1. 今の文書の枕言葉と、精緻化したコンセプトの差

| 文書・節 | 今の言い方 | 差 |
|---|---|---|
| `docs/PRD.md` コンセプト | 「伝える準備ができているかを確かめる」訓練 | 確かめる＝診断的。復習・思い出すの語がない |
| PRD 目的 | 「代わりの手段」「未確認のこと」に「気づいてもらう」 | 役割の記述まで。最終目標（伝えられる状態）がない。KEEP-THINKING 11-03 が既に指摘済み |
| PRD 体験の核（ADR-0019） | 伝える→使えなくなる→立て直す→気づきと準備 | 「立て直し」は体験の形。復習の目的と矛盾しないが、つながりが書かれていない |
| PRD 評価の方針 | 点数なし、手薄なところを示す | 復習と整合する。変更不要 |
| `README.md` 何をするアプリか | 「気づいてもらうことが目的」 | 同上 |
| `docs/demo-script.md` 0:00–0:20 | 訴求文と課題 | 「復習」の視点なし |
| `docs/KEEP-THINKING.md` 11-03 企画検討 | 役割＝「準備の状況を振り返り…気づけるよう支える」 | **最も近い**。「PRDの目的の書き方を直すか」がオーナー判断待ちのまま |

要するに、文書は「気づき」「伝える準備」「立て直し」で書かれ、「復習・思い出す」は未登場。ただし意味は衝突しておらず、**目的→役割→手段の階層が書かれていないだけ**。KEEP-THINKING の整理（最終目標／役割／5観点＝手段）をPRDに持ち上げれば足りる。

#### 2. 書き直す文書と最小限の変更

- **`docs/decisions.md` ADR-0022（新規、提案中）**：「SonaQuestの役割を、災害時に自分の服薬情報を伝える準備を**思い出し、振り返る（復習する）きっかけ**と定める」。背景にKEEP-THINKING 11-03 と Issue #12 を引く。決定に「復習の対象は5観点の準備状況。薬の名前を思い出せるかは評価しない（ADR-0009・0021）」を明記。影響にPRD・README・demo-script・evidence を列挙。`TODO-OWNER マーカー` を付ける。
- **`docs/PRD.md` 目的**：冒頭に3行追加。「最終目標：普段の情報源が使えなくても自分の服薬情報を周囲に伝えられる状態に近づく」「SonaQuestの役割：短い対話で、伝える準備を思い出し振り返るきっかけを与える」「5観点・出来事・立て直しはそのための手段」。既存の本文は残す。
- **`README.md` 何をするアプリか**：1文追加（「自分の伝える準備を思い出し、振り返るきっかけにしてもらうアプリです」程度）。
- **`docs/evidence.md` インパクト**：主張「伝える準備を振り返るきっかけになる」を**未検証**で1行追加。効果として書かない（KEEP-THINKING「捨てた案」）。
- **変えないもの**：訴求文「もしもの時、自分の薬のことを伝えられますか？」と「お薬の避難訓練」（オーナーが2回決定、マーカー付き）、5観点の名前と定義（KEEP-THINKING「PRDを正とし変えない」）、体験の6段階と3画面（ADR-0019）。

#12 で案Aを選ぶなら、上の文は「架空の人物で練習し、**自分の**準備を振り返るきっかけにする」と書き分ける必要がある。案Bなら `content.ts` の案内と回答欄の文言を質問ごとに変えるコード変更が伴う。小さいが凍結前のコード変更なので、**唯一の境界線上の項目**としてオーナーが判断する。

#### 3. 今の固定質問は「復習のきっかけ」として働くか

中身としては働く。`FIRST_HALF_QUESTIONS` の2問目（何を見れば確かめられるか）、`RECOVERY_QUESTION`（ほかにどう伝えるか）、`RECENT_QUESTION`（記録は最新か）、`PROXY_QUESTION`（誰が知っていて連絡できるか）は、どれも本人の準備を思い出させる問いになっている。ただし次の2点で弱い。

- 全回答欄が「架空の内容で」なので、思い出す行為が起きない（#12 の論点3そのもの）。
- 1問目（薬の名前・量・何の薬か）は、架空で答えさせる限り復習にならない。ADR-0021 の「答えられるかどうか自体が気づきの材料」も、架空では成立しない。

一方、復習の仕掛けはすでに2か所ある。`UNDETERMINED_NOTE`「回答をそのまま読み返して、手薄なところを探してみてください」と `DONE_NOTE`「メモや予定表に書いておきましょう」。新しい画面を作るより、この2つを「復習」の文脈で言い直すのが最小の手当て。

#### 4. 「繰り返せる復習」にするには（すべてスコープ変更の候補）

保存しない方針（ADR-0007、privacy.md）を守りながら、利用者が**自分で持ち帰る**形だけが候補になる。

- 振り返り画面に「手薄なところ＋選んだ準備行動＋いつやるか」だけを利用者がコピーできるボタン（固定文＋選択値の組み立て。架空の薬の回答は含めない）。
- 選んだ「いつやるか」から `.ics` を端末に書き出す。
- 「次は○か月後にもう一度」という固定文の案内（通知やリマインダーは持たない）。

注意点：`scope.md` 作らないものに「履歴、共有」がある。共有シートや書き出しは「共有」と読まれうるので、**オーナーがスコープ変更として判断**し、#16 roadmap に置くのが安全。実装するとしても、持ち帰る文は固定文と利用者の選択だけで作り、Claudeに要約・言い換えさせない（safety.md「発言の要約・言い換え・創作をしない」）。凍結前には着手しない。

#### 5. 安全上の注意（「思い出す」の言い回し）

KEEP-THINKING 11-03 が既に警告しているとおり、家族の言葉は薬の名前の暗記と読まれる。公開文（README・PRD・デモ・UI）では必ず「**伝える準備を**思い出す・振り返る」と書き、「薬を思い出す」「薬の名前を言えるようになる」とは書かない。ADR-0009・0021「薬の名前を言えるかは評価しない」と整合させる。「思い出せるようになる」を効果として書かない（未検証）。

#### 6. デモ台本

KEEP-THINKING の冒頭案「お薬手帳もスマホもない。避難所で飲んでいる薬を聞かれたら…」は復習のコンセプトに合うが、(a) 複数の情報源を同時に失う場面で仕様（1つだけ失う）と違う、(b)「飲んでいる薬を聞かれたら」が薬の暗記に寄る。0:00–0:20 は「手帳もスマホも手元にない。あなたの薬のことを、どうやって伝えますか？」のように**伝える手段**で問いかける案を、採用の判断材料として残す。撮影前の judge-audit は維持。

#### 7. やらないこと

- KEEP-THINKING の家族のやり取りをREADME・PRD・デモに持ち込まない（CLAUDE.md 絶対ルール8。KEEP-THINKING も証拠にしないと明記）。

- 訴求文・5観点・6段階を書き換えない。既存の `TODO-OWNER マーカー` を触らない。
- 「復習で伝えられるようになる」を実証済みのように書かない。
- 凍結前に #12 の案B以外のコード変更を増やさない。STATUS の鮮度は別ブランチ（docs/13-status-sync）が扱っているので重ねない。

### 観点3：安全・プライバシー・規制

#### 前提と結論（SAFETY・PRIVACY・規制の見え方）

main（e82667a）を読んだ範囲では、規則（`.claude/rules/safety.md` 22行）はすでに ADR-0021・ADR-0009（架空のみ）に合わせて直っており、**規則と ADR の正面衝突はない**。問題は3点に集約される。

1. 「実装済みでないものを現在形で書いている」箇所が README・PRD に残る（絶対ルール10、凍結前に直すべき）
2. オーナーの新しい一文「**自分の**薬の情報を**思い出す**」が、提出版の「架空の内容で答える」（ADR-0009）と、公開文書の中でまだ両立させられていない（Issue #12 の範囲）。これを README/PRD に書く前に #12 を決める必要がある
3. 「思い出す＝正しく思い出せた」と読まれる余地と、「服薬管理・記録アプリ」「医療機器」に見える余地を、文言で先に塞いでおく必要がある（新規の文章が要る）

#### 1. 食い違い・古い記述（既存文書の修正。凍結前に最優先）

- **自動の中断を現在形で書いている**：`README.md`「安全と限界」73行「体調の訴えらしい入力では訓練を中断し、固定の案内を表示しますが…」、`docs/PRD.md`「要件」325行。同じ README の表34行と `docs/STATUS.md`、Issue #14 は「未実装」。→「完成版では〜する予定」か、試作版の範囲を明記する時制の修正だけでよい。新しい機能説明を足さない。
- **「音声対話」**：`README.md` 3行、`docs/PRD.md`「目的」、`CLAUDE.md` 3行。ADR-0004・0005 は未確定、STATUS は音声未着手、#17 で実機要件も外した。提出版で音声を作らないなら「対話（文字入力。音声は未定）」へ。ここが残ると、デモ台本で映せないものを README が約束する形になる。

#### 2. 「思い出す」の位置づけと免責（新しく書く内容）

オーナーの一文を公開文書に入れるなら、同じ場所に次の限定を必ず添える。置き場所は `README.md`「何をするアプリか」「安全と限界」、`docs/PRD.md`「コンセプト」「目的」、`content.ts` の `INTRO_POINTS` と `JUDGMENT_NOTE`。

- **思い出した内容が正しいかは確かめない**。「確認できた」は説明できたという意味（ADR-0017 の意味の限定をそのまま流用）。
- **思い出せなかったことは失敗ではなく気づき**（ADR-0017 の「未確認と気づいた」、ADR-0019 の点数・合否なし）。
- **アプリは思い出す手助け（ヒント・候補・補完）をしない**。ここが新しい。ADR-0021 で薬の名前を聞く以上、「思い出せない」と答えた利用者に Claude が候補や一般的な量を示すことが、唯一の「推定」経路になる。`.claude/rules/safety.md`「Claude（アプリ内）がしないこと」に「思い出させるための候補の提示・補完」を1行足すか、ADR-0021 への追記で明示する。
- **語の選び方**：公開文には「思い出す**きっかけ**」「振り返る」を使い、「復習」「確認（検証の意味）」は避ける。「復習」は正解がありアプリがそれと照らす印象を与え、審査の「医療アドバイスAIに見える表現」（`judge-audit` 手順5）に引っかかる。`SCENE_INTRO`「普段飲んでいる薬を確認しています」は聞き取りの意味なので可。ただし結果画面の「確認できた」と二重の意味になる点は `JUDGMENT_NOTE` が受けている。

#12 との関係：「**自分の**薬を思い出す」は本人のことで、`INTRO_POINTS` 3項目目「架空の人になったつもりで」と両立しない。#12 の A/B/C を選ぶ判断基準をこのレンズで言うと、**実際の薬の名前が入力欄に打たれるか**が分岐点。打たれる設計（B の一部・将来の実在版）は、要配慮個人情報の入力、Claude 連携後の外部送信、「服薬管理アプリ」に見える、の3つを一度に引き受ける。打たせない設計（C：言える／一部言える／言えない の選択）は「思い出せたか」の自己申告を本人のこととして扱えて、ADR-0009 の架空方針も保てる。結論は出さず、#12 の比較表にこの軸を足すことを勧める。

#### 5. Phase 2 のプロンプト制約（#15「決めることの表」に入れる項目）

表そのものはここで書かない。項目として入れるべきもの：

- **「わからない」は `aware_unconfirmed`**。思い出させる誘導（「もう少し思い出してみて」）をしない。
- **回答が架空か実在かに言及・推測しない**（ADR-0009 の方針は「案内」であり、Claude の判定対象ではない）。
- **要約・言い換えなし**（既存）。原文は端末内から表示（ADR-0009 必須事項5）。
- **出力は構造化のみ**（ADR-0015）。聞き返しを自由文にするかは `docs/architecture.md`「自由文を返させるかは未確定」。提出版は**観点別の固定テンプレ（ID から引く）を推奨**。理由：S12 の検査を実装せずに済み、薬名推定の漏れ口が閉じる。
- `emergency` は補助、主は語の照合（ADR-0011）。Claude に緊急度を判断させない文言。
- ログ：本文・プロンプト・応答を `console.log` に出さない。`wrangler` の observability 設定を ADR-0007 に揃え、設定値を ADR-0007 に追記（`privacy.md` の要求）。
