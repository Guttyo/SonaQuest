## 助言の要旨（ChatGPT の最後の提案）
目標は「自分では大丈夫だと思っていた。でも、実際に試してみると、伝えられないことがあった」を、利用者自身に発見してもらうこと。

1. **5つの体験**：予想する → 伝えてみる → 失ってみる → 立て直してみる → 発見して備える
2. **「不足を教える」のをやめる**：結果の表で「代わりの情報源：確認していない」と示すより、頼っていたものが使えなくなった場面で本人に考えてもらう。答えられなくても「備えがない」と断定せず、「今回の訓練では確認できなかったこと」として扱う
3. **画面**
   - A 対話：チャット履歴ではなく「今いる場面」を見せる。係・場面・いまの質問・回答の操作を中心にし、履歴は常時見せない
   - B 出来事：通常の対話と明確に切り替える（暗転、使えなくなったものの表示）。出来事の種類ごとに演出を変え、係の交代では別のパペットが登場する
   - C 振り返り：5観点の判定より先に「今回、気づいたことは？」を本人が選ぶ欄を置き、AI の判定と本人の気づきを分ける。次にできることへつなげる
4. **トランジションは意味がある場所に限る**（訓練開始、質問の変更、音声入力、情報源の選択、災害の発生、結果の表示）。読み上げ・回答・中断を妨げない。動きを減らす設定でも同じ内容が伝わるようにする
5. **リファクタ**：進行（training.ts、rules.ts）・安全判定・送信・2D への戻りは維持し、表示の層（場面の導出、舞台、質問、出来事、気づきの表示）を分ける。アニメーションの完了で進行を進めない
6. **成功の測り方**：状況を理解できたか、自分の備えについて発見があったか、次の行動が具体化したか。「不足を感じさせること」を成功の指標にしない
7. **今回やる範囲**：現在の質問が主役の画面、情報源のカード選択、災害イベントの明確な場面転換。余裕があればパペットの反応、会話の切り替え、結果画面の気づきの選択。提出後に、導入の自己予想、イベントを早く起こす質問順、訓練時間の短縮、繰り返し体験

## 助言に無かった、「気づき」を強める小さな変更
いずれも `Review.tsx`・`Done.tsx` と固定文の変更で、Claude の出力は増やさない。ただし反証で、新しい固定文はすべて TODO-OWNER マーカー付きの下書きになる（凍結の直前にオーナーの確認待ちを増やす）ことと、点数・合否に見えない条件が要ることが分かったので、凍結の前に入れるのは N3 と N4(b) だけにし、残りは条件を付けて凍結の後に回す。

| ID | 変更 | 狙い | 根拠と条件 |

## ADR 案の下書き（G4：振り返りの「気づいたこと」の自己選択）
