# 提出動画の BGM と効果音をコードで合成する

- 日付：2026-11-08
- 対象：Issue #272（ブランチ `feat/272-video-demo`）。主なコミット：`9915d48`（合成のスクリプト2本と、曲ごとの大きさの合わせ）、`bcae6df`（BGM と効果音の置き場 `video/src/soundtrack.tsx` と、アプリの BGM の書き出し `video/scripts/capture-app-bgm/`）
- 関係する ADR：ADR-0051 の追記（「BGM と効果音」の項。訓練はアプリの BGM をそのまま敷き、ほかの曲と効果音は外の素材を使わずコードで合成する）

## 背景

提出動画（180 秒、13場面）を書き出して見たオーナーが、BGM が入っていないことに気づいた（2026-11-08、チャット）。訓練の場面（4〜6番）は、アプリの BGM（`web/src/bgm/bgm.ts`。Web Audio でその場で鳴らす、ポップな音）をそのまま使うことになった。残りの場面に合う曲は、本編を組んでいたセッションが、新しいセッションに作らせた。続けて、効果音も頼まれた（「効果音とかもね！作ろうね！」）。

条件は次のとおり。

- 外の音源・サンプル・ループを使わない。依存パッケージを足さない（足すにはオーナーの承認が要る）。
- ナレーション（日本語、やや速い）が全編に乗る。声の帯域（おおよそ 300 Hz〜3 kHz）と、大きく込み入ったメロディを避ける。
- 長さは場面の秒（`video/src/sections.ts`）にちょうど合わせる。48 kHz・ステレオ・16 bit の WAV にし、頭と終わりに 0.5 秒のフェードを付ける。
- 書き出し先は `video/public/bgm/`・`video/public/sfx/`（Git の対象外）。

## やったこと

### BGM 4本（`video/scripts/compose-bgm.mjs`）

調とテンポは、訓練の BGM（ハ長調・120 BPM・C–G/B–Am–F）に合わせた。音域は合わせていない。訓練の BGM はメロディが C5〜C6 で声の帯域にあるが、こちらはナレーションを避けて低音寄りにした。

| ファイル | 場面 | 長さ | 調・テンポ | ねらい |
|---|---|---|---|---|
| `bgm/opening.wav` | 1〜3番 | 33 秒 | イ短調・60 BPM | 静かで少し張りつめた音。頭の黒（1.0 秒）の後、問いの文字が出る所で高い鈴を1つ鳴らす（はじめは暗転の録画の後の 2.6 秒だったが、コミット `1e09657` で録画を外して 1.0 秒に移した）。2番は1秒ごとに心音のような低い打音を入れる。3番は Am–F–C–G で進み、G から訓練のハ長調へ渡す |
| `bgm/board.wav` | 7〜10番 | 61 秒 | ハ長調・120 BPM | 仕事が着実に進むリズム（F–G–Em–Am）。8番の早送りの札の区間（22〜26 秒）は、テンポを変えずに刻みを16分に倍にする。9番は掲示板の5つの役として、左から右の5か所で短い鈴を鳴らす。58 秒に C へ着地する |
| `bgm/models.wav` | 11番 | 9 秒 | ハ長調・120 BPM | 軽く、技術の感じ。Cmaj7–Dm7–Em7–Fmaj7 と上がり、Gsus4 で次へ渡す |
| `bgm/ending.wav` | 12〜13番 | 20 秒 | ハ長調・120 BPM | 温かく、希望のある音。16 秒に C へ着地する。着地では、訓練の BGM の頭の音（ミ・ソ・ド）を1オクターブ上の鈴で鳴らし、残りの4秒で自然に消える |

作り方：
- 音はサイン波と、倍音を切った三角波・のこぎり波だけで組む。
- 和音と伸ばす音は 300 Hz より下に、鈴は 1.3 kHz より上に置く。
- 残響は Freeverb の形をスクリプトの中で組んだ。
- 音の大きさは、BS.1770 の計算（48 kHz の K 特性の係数、ゲート付き）をスクリプトに入れて −24 LUFS にそろえる。
- 乱数は種を固定しているので、作り直しても毎回同じ音になる。

### 効果音6本（`video/scripts/compose-sfx.mjs`）

| ファイル | 長さ | 山 | 使い道 |
|---|---|---|---|
| `sfx/tap.wav` | 0.100 秒 | −12 dBFS | 画面のタップ |
| `sfx/whoosh.wav` | 0.600 秒 | −9 dBFS | 章の題（音の高さを上げながら左から右へ流す） |
| `sfx/battery-off.wav` | 0.800 秒 | −8 dBFS | 5番の電池切れ（下がっていく鈍い音と、最後の低い打音） |
| `sfx/confirm.wav` | 0.500 秒 | −9 dBFS | 発注の承認・人の確認（ソ→ドの2音の鈴） |
| `sfx/pop.wav` | 0.100 秒 | −12 dBFS | テロップ・札が出る |
| `sfx/tick.wav` | 0.050 秒 | −14 dBFS | 早送り・数え上げ（BGM の刻みと同じ形） |

山はファイルごとに決めた値にそろえた（スクリプトの `PEAKS`）。鳴らす大きさは Remotion 側で決める。本編のセッションが、合成した BGM 全体を `BGM_VOLUME = 0.3`、効果音を `SFX_VOLUME = 0.5` にした。アプリの BGM は −20 LUFS で書き出されているので、`gain: 0.63` で合成の曲に合わせた（`video/src/soundtrack.tsx`、コミット `9915d48`）。

### 試聴のページ（`video/public/listen.html`、Git の対象外）

BGM 5本（訓練のアプリの BGM を含む）を動画の順に並べて通しで聞けるページと、効果音を1つずつ鳴らすボタンを作った。オーナーは開いた後、チャットで「最高だぜ」と返した。

## つまずいたことと教訓

- **大きさを曲全体でそろえると、問いの場面がほかと同じ大きさになった。** −24 LUFS は曲全体の積分値でそろえるので、1番（問い）の1秒ごとの大きさも、2・3番とほぼ同じ約 −24 になった。1番の持続音と低音を下げ、1番を約 −28、問いの鈴の所を約 −26 にして、2番の頭で一段上がるようにした。→ 次に場面の境目がある曲を作るときは、そろえた後に1秒ごとの大きさ（ffmpeg の `ebur128` の M）を場面の境目と並べて見る。
- **ナレーションを避けた結果、上のきらめきがほとんど聞こえなかった。** 最初の版では、3 kHz より上の帯域が 300 Hz 以下より 25〜33 dB 小さく、小さなスピーカーでは低音だけが残る形だった。仕上げ前の点検で指摘を受け、鈴・刻み・ハイハット・データの音を `HIGH_GAIN = 2`（+6 dB）で持ち上げた。持ち上げた後は 20〜26 dB 小さい。声の帯域には触れていない。→ 声の帯域を避けるときは、避けた帯域だけでなく、上下の帯域の大きさの比も測る。
- **1秒に1回の測り方では、拍の頭の音が見えなかった。** 11番は、1秒ごとの M（毎秒 x.99 の 400 ms）が −27〜−29 なのに、積分値は −24 だった。キックが偶数秒の頭にあり、x.99 の窓から外れていたため。「軽く」という曲でキックが大きさを担っていたので、キックを半分にした。→ 短い曲は、0.1 秒ごとの M の最大と中央値を見る。
- **アプリ内のブラウザでは、ローカルの HTML から同じフォルダの音を読めなかった。** 内蔵のブラウザはローカルの HTML を `data:` の URL として開くので、`bgm/opening.wav` のような相対パスが解決できず、`audio` が読み込みの失敗（`error.code` 4）になった。既定のブラウザで開き直した。→ ローカルの音や動画を試すページは、初めから既定のブラウザで開く。

## 確かめたこと（2026-11-08、Windows 11、Node.js v26.13.0、ffmpeg の ebur128・astats・ffprobe）

- 長さ：サンプル数が 1,584,000／2,928,000／432,000／960,000（33／61／9／20 秒）で、ちょうどだった。効果音6本は、上の表の長さだった。形式は 48 kHz・2 チャンネル・16 bit。
- 大きさ：BGM は4本とも積分 −24.0 LUFS で、スクリプトの BS.1770 の計算と ffmpeg が一致した。サンプルの山は opening −10.5、board −9.8、models −8.4、ending −12.1 dBFS。
- 帯域：300 Hz〜3 kHz の RMS は、300 Hz 以下より約 11〜17 dB 小さい。
- 効果音の山は `PEAKS` のとおり（ffmpeg の astats で −8.0〜−14.0 dBFS）。
- 作り直し：`node video/scripts/compose-bgm.mjs`（約 15 秒）と `node video/scripts/compose-sfx.mjs` が、どちらもエラーなく終わる。

## 推測

- 作ったセッションは音を聞けないので、上の値は測った値だけで、聞こえ方は確かめていない。低音寄りなので、ノートPCのスピーカーではまだ小さく聞こえるかもしれない。そのときは `HIGH_GAIN` を上げる。
- tap・pop・confirm は声の帯域（1〜2 kHz）にかかる。短いので邪魔にはなりにくいと考えたが、ナレーションの言葉の途中に重なる所では、Remotion で小さくするほうがよい。

## 残ること

- ナレーションの mp3 を合成した後に、重ねて聞き、BGM と効果音の大きさ（`BGM_VOLUME`・`SFX_VOLUME`・曲ごとの `gain`）と、訓練の BGM とのつなぎ目を直す（Issue #272 の残り。STATUS.md の「ナレーションの合成（オーナー）と、その長さに合わせた時刻・BGM の大きさの調整」）。
- 場面の秒を変えたら、`compose-bgm.mjs` の `SCENES` と、8番の早送りの区間（`ffFrom`・`ffTo`）を一緒に直す。
