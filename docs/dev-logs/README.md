# 開発記録（dev-logs）

1つのテーマ（PR、調査、設計の変更、Phaseの区切り）について、経緯・理由・教訓を詳しく残す場所。後から読んだ人が、何があって、なぜそうしたかを組み立て直せるだけ書く。

書くときは `dev-log` Skill（`.claude/skills/dev-log/SKILL.md`）を使う。

## ほかの記録との違い

| 記録 | 書くこと | 書き方 |
|---|---|---|
| `docs/KEEP-THINKING.md` | 作業1回ごとに何があったか | 短い日誌。追記のみ |
| `docs/decisions.md` | 決めたこと（決定・理由・却下案・影響） | ADRごと |
| `docs/dev-logs/` | 決めるまで・直すまでの経過と、次に同じことで迷わないための教訓 | テーマごとに1ファイル |

- 決定そのものは ADR に書き、dev-log からは ADR番号で参照する。
- 実験や実測の結果の数値の正は `docs/evidence.md`。dev-log には経過と考察を書く。

## いつ書くか

次のどれか1つに当てはまるとき。

1. PRで自動レビュー・人のレビューが2回以上あった
2. 安全（`.claude/rules/safety.md`）・プライバシー（`.claude/rules/privacy.md`）・外部送信・ログの扱いを変えた
3. モデル比較など、実験や実測をした（結果の数値の正は `docs/evidence.md`。dev-log には経過と考察を書く）
4. Phase が終わった
5. 作業1回では終わらない調査をした

## 書かないとき

- 誤字・言い回しだけの修正
- 1ファイルの小さな修正
- 既に記録したこと

## ファイル名

`YYYY-MM-DD-<テーマを表す英小文字とハイフン>.md`。日付はテーマを書き終えた日。
