## 背景
Phase 2 の前に決めることの表（`docs/phase2-decisions.md`）の決定に沿って、Cloudflare Workers の `/api/turn` を作り、画面から呼ぶ。本物の Claude API は、オーナーの判断で呼ばない（課金をしない）。確かめは、偽の返事を渡す単体試験と、Claude を呼ばない経路の画面の操作で行う。

## やったこと
- `web/worker/`（Hono）：
  - 入力の検査。大きすぎる入力や形の違う入力は、Claude を呼ばずに拒否する。
  - Claude の呼び出し。`claude-opus-5-5`、effort low、構造化出力、8秒、SDK の再試行0回、`fallbacks: "default"`。
  - 出力の検査と、Claude が作った文の検査（長さ・禁止表現・利用者の言葉の繰り返し）。
  - 開発中だけの本文のログ。
- `web/src/flow/`：
  - `/api/turn` のやり取りの形（`turnContract.ts`）と、ブラウザからの呼び出し（`api.ts`）。
  - 進行（`training.ts`）。返事を待つこと、聞き返し、質問し直し、思い出せない回答への固定文、③確認の初期選択、失敗時の固定の進行、緊急の種類。
- 依存を3つ足した（オーナーの承認）：`@anthropic-ai/sdk` 1.3.0、`hono` 4.13.14、`wrangler` 4.156.0。公開から1週間前後の版を選んだ。

1回目の主な指摘：
- **Workers が起動しない。** Workers の入口（`index.ts`）が `default` のほかに数値の名前を出していた。workerd はその名前を入口として読み、起動を拒んだ。単体試験・型の検査・まとめ（dry-run）では見つからず、`wrangler dev` を動かして初めて分かった。
- **文の検査の見逃し。**
  - 推測の確かめ：「〜でしょうか」「〜のようですね」。
  - 2文字の病名（喘息、血圧）の繰り返し。
  - ひらがなで書いた薬の名前の繰り返し。
  - 漢数字の用量（二錠）。
  - 安心させる判断：「大丈夫です」「様子を見ましょう」。
- **質問し直した入力の再送。** 関係のない話として質問し直した入力を、その後のやり取りのたびに Claude に送り直していた。
- **自傷のほのめかしの案内の取り違え。** Claude が自傷のほのめかしを見つけても、体調の訴え用の案内（119番）を出していた。

## つまずいたことと教訓
- **Issue のコメントを読まずに、オーナーに選択肢を出した。**
  - Issue #15 のコメントには、Phase 2 の決定の表がすでにあった。読まずに AskUserQuestion で選択肢を出し、その答えで決定の行を書いた（PR #33）。
  - 6項目が違い、訂正の PR（PR #38）と、実装の直しが要った。
  - 着手の前と、オーナーに聞く前には、Issue の本文とコメントをすべて読む。
- **型と単体試験が通っても、Workers が起動するとは限らない。**
  - Workers の入口の制約（`default` 以外を出さない）は、型の検査にもまとめにも出ない。
  - 入口が `default` だけを出すことを単体試験にし、手元で `wrangler dev` を一度動かす。
  - API キーを置かない状態なら、Claude は呼ばれない。
- **語の照合は、言い回しの変種に弱い。**
  - 「〜ではないですか」は止めていたが、「〜でしょうか」は止めていなかった。
  - 4文字の並びで見る繰り返しの検査は、2文字の病名を見逃した。
  - 検査の語を足すときは、同じ意味の言い回しの変種と、短い語を一緒に試験に入れる。
  - 迷うものは捨てる側に寄せる。誤って捨てても固定文に戻るだけで、画面に危ない文は出ない。
- **Dropbox が `node_modules` をオンラインのみにすると、vite と vitest が止まる。**
  - `npm install` の後しばらく、`web/node_modules` のファイルが Dropbox のプレースホルダー（ReparsePoint）になった。
  - vite の読み込みが数分かかり、vitest の作業プロセスが起動しなかった。git の操作も遅くなった。
  - 時間がたって同期が落ち着くと、元に戻った。
  - 環境はオーナーが整える決まりなので、回避策は選ばずに待った。ADR-0018 の「GitHub から Dropbox の外へ clone する」移行を早めるかは、オーナーの判断。
- **開発中の React の StrictMode で、effect が2回動く。**
  - 回答のたびの問い合わせを effect で送ると、取り消しても Workers 側で Claude が2回呼ばれうる（課金が2回）。
  - 「何回目の訓練か」と「入力の件数」の組で、同じ問い合わせを送り直さないようにした。
  - 古い返事は reducer で捨てる。

## 確かめたこと

- 2回目のレビュー：確かめられた8件は、すべて文の検査の見逃しだった。

## 追記：本物の Claude API での通し（2026-11-04）
- オーナーが API キーを `web/.dev.vars` に置き、10回前後の呼び出しを承認した。使ったのは8回。
- **最初の2回は curl で呼んだ。** Claude は「文字がうまく表示されず、回答を読み取れませんでした」と聞き返した。開発中だけのログで出力を見ると、Git Bash の curl が日本語を UTF-8 で送らず、文字化けした回答が Claude に届いていた。
  - 送る内容を手元で組み立てて確かめ、アプリの問題ではないと分かった。
  - 日本語を含む API の試しは、ブラウザから行うか、UTF-8 のファイルを `--data-binary @file` で渡す。
- **ブラウザから、架空の回答で訓練を1回通した。**
  - 6回の呼び出しは1.6〜3.5秒で返った。
  - Claude の言い回しが4回、検査を通って画面に出た。別のモデルでの答え直しは無かった。
  - 判定は、回答の中身に沿っていた。記録が最新か分からないと答えた観点は「未確認と気づいた」、ほかは「確認できた」。
- **答えたモデル名をログに出すようにした。** 別のモデルで答え直したときに分かるように、答えたモデルの名前を Workers のログに出す。モデル名は本文ではないので、公開する版でも出してよい。
- 開発中だけのログ（本文を含む）は、確かめた後で消した（`.claude/rules/privacy.md`）。

## 追記：応答を自然にする（ADR-0029、2026-11-04）
- **ADR-0029 が出てきた経緯**：オーナーが別のセッションで訓練を通し、聞き取り係の応答が不自然だと感じて、ADR-0029 を提案中で書いた。
- **比較実験の値を足した**：Claude Code が比較実験の値を ADR-0029 に足した。捨てられた3回はすべて「大丈夫」で、半分の最後には受け止めが出ていなかった。
- **オーナーの提案と決定**：オーナーは、Claude を呼ぶときのシステムプロンプトを足して直すことを提案した。そのうえで、受け止めは「Claude の一言＋固定文の予備」、「大丈夫」は「プロンプトと例外の両方」と決めた。
- **教訓**：検査で捨てられる文を減らすには、検査を緩める前に、まずプロンプトで文の作り方を伝える。
  - 検査（固定文に戻す守り）は残したまま、Claude に「どの回答にも使える決まった受け止め」「大丈夫を使わない」「半分の最後も一言を書く」と伝えた。
  - それだけで、捨てられる文が無くなり（17/17）、半分の最後の受け止めも5/5で出た。
  - 例外（「ゆっくりで大丈夫」）は、プロンプトだけで防ぎきれないときの受け皿として足した。
