## 背景
ADR-0031 で、音声は 3D の対話モードだけで使い、提出に必須（A-15・A-16）になった。3D のパペット（#37）は別のセッションが同時に作っていたので、受け持つファイルを分け、Listener に渡す値（mode・activity・relief）だけを取り決めて並行で進めた。オーナーは、マイクを「押して話す」にすること、2D の姿に戻っても声は残すこと、ElevenLabs は有料プランで使うことを選んだ（ADR-0033 の決定の行）。

## つまずいたことと教訓
- **作業コピーに秘密情報のファイルが無く、ElevenLabs の本物の音声を試せなかった。** `wrangler dev` の起動の表示に変数の一覧が出ず、`/api/tts` は `tts: no_api_key` を返した。Issue #41 の dev-log（2026-11-04-ten-answers.md）と同じつまずき。次に本物の API を使う作業を worktree で始めるときは、最初に `wrangler dev` を起こして起動の表示とログの種類だけで有無を確かめ、無ければ着手の時点でオーナーに置いてもらう。
- **Claude desktop のブラウザ画面はマイクを使えない。** 押して話すは、マイクの拒否の経路としては本物で確かめられたが、声を聞き取る経路は、ページの中で音声認識を偽物に替えて確かめるしかなかった。本物のマイクでの確認（safety-test-plan V9）は、オーナーの手元のブラウザで行うものとして、最初から残件に書く。
- **音声の `src` を空にすると、終わった読み上げの後に切り替えが起きた。** 書いている途中で、`speaker.ts` の URL を手放す処理で `src` を空にしていた。ブラウザによっては空の `src` で error が起き、`onerror` がブラウザの読み上げへの切り替えを呼ぶ。`src` は変えず、URL だけを手放すようにした。次に音声の要素を使い回すときは、後始末で `src` を書き換えない。
- **時間切れで切り替えた後、止めた処理の失敗でもう一度切り替えていた。** `speaker.ts` の `fallback` で、取りに行く処理を止めると AbortError が来て、同じ番号のまま失敗として扱われていた。切り替えのときに番号を進め、古い処理の知らせを捨てるようにし、`speaker.test.ts` で切り替えが1回だけであることを確かめた。
- **マイクを拒否されても、次の質問でまた「押して話す」が出た。** 回答の欄は質問ごとに作り直される（`key`）ので、拒否の状態も消えていた。ブラウザ画面で確かめて見つけた。拒否はその回のあいだ `Dialogue.tsx` で覚えるようにした（`hooks.ts` の `lostMic`）。部品を作り直す画面では、その回のあいだ残す状態を親に置く。
- **作業の間に main が2回進んだ（PR #59、PR #60）。** push の前は載せ直し、push の後は main の取り込みにした（強制の push は使わない）。取り込みで STATUS.md がぶつかったとき、両側の行に `[TODO-OWNER]` の語が入っていて、重なった片方を消す編集をマーカーの保護の hook が止めた。STATUS.md は main の版を取り、自分の行を足し直した。次に STATUS.md がぶつかったときは、最初から main の版を取って足し直す。
