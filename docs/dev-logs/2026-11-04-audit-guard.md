# 監査役の Claude を /api/turn に入れる（Issue #40）

- 日付：2026-11-04
- 対象：Issue #40、ブランチ `feat/40-audit-guard`。コミット 6ffab99（本体）、6233f29（レビューへの対応と STATUS）
- 関係する ADR：ADR-0030（監査役）、ADR-0025（Claude が作る文と検査）、ADR-0028 の6（待ち時間）、ADR-0020（光の存在と動きを減らす設定）、ADR-0011（緊急時の中断）、ADR-0007（ログ）

## 背景
聞き取り係の Claude が作った文は、Workers の語の照合（`web/worker/checks.ts`）で確かめていた。監査役の比較実験（docs/evidence.md「監査役の比較」）では、止めるべき文18件のうち6件が語の照合を通り、Haiku 5.5 の監査役は3回とも18件すべてを止めた。オーナーは、この結果を根拠に Issue を立てて本番に入れるよう指示した。あわせて、返事を待つ間の「考え中」の表示を求めた（「即答されるとビビる」）。

## やったこと
- `web/worker/turn.ts` の `runTurn`：語の照合を通った文だけを監査役（`web/worker/audit.ts`）に送る。止めたとき・失敗したときは、その文だけを捨てて固定文に戻す。判定と次の手はそのまま使う。
- 監査役に渡す固定の質問文は、実験と同じ渡し方にした（`auditedQuestion`。次へ進むときは次の質問、聞き返し・半分の最後はいま答えた質問）。実験の材料（`web/experiments/audit-cases.mjs`）の `fixed_question` を読んで合わせた。
- `web/worker/app.ts`：ログに止めた理由と失敗の種類だけを出す。測った値の見出しに監査役の結果を載せる。監査役の作り方を差し替えられるようにした（試験で本物を呼ばないため）。
- `web/worker/devlog.ts`：手元の比較実験のときだけ `DEV_AUDIT=off` で監査役を外せる。
- 画面：待つ上限を9秒から16秒にした（`web/src/flow/api.ts`）。返事を待つ間、光が明滅し、文の後ろに点が流れる（`Dialogue.tsx` の `Thinking`、`styles.css`）。
- 文書：ADR-0030、`.claude/rules/safety.md`、architecture、README と初回画面の送信の説明、safety-test-plan（S20・P12）、evidence（監査役を入れる前と後）。

確かめられた指摘：
- **緊急のときも監査役を呼んでいた。** Claude が `symptom`・`self_harm` を返すと、画面は文を使わずに中断の案内を出す（`web/src/flow/training.ts`）。それなのに Workers は監査役を待ってから返していた。本物の API の実験で、症状の件（E1）は監査役に約2.3秒かかっていた。Workers と文書の2つの観点が、別々に見つけた。緊急のときは監査役を呼ばないように直し、試験を足した。
- **試験計画の状態の行と、各行の結果が食い違った。** 状態の行で S9・S16〜S19 などを「実施」に足したのに、各行は「未実施」のままだった。各行を「実施の記録」に向けた。安全と文書の2つの観点が、別々に見つけた。
- **「Claude の文が画面に出た」と書いたが、緊急の2件では出ない。** 数えていたのは検査を通った数だった。「検査（と監査役）を通った」に直した。
- **STATUS.md を更新していなかった。** PR の前に直す予定だった（ADR-0023）。

反証された指摘：
- 料金の比の「約18倍」が、違うプロンプトの結果どうしの比になっている。反証役によれば、同じプロンプトでは約14倍、定価では20倍で、18倍はその間の目安として外れていない。
- 本物の API の記録を S20 の行に置いている。反証役によれば、止める場面が起きなかったことと、単体試験を見ることを記録に書いているので、言い過ぎではない。
- README と初回画面の「回答は送らない」が強すぎる。反証役によれば、監査役の呼び出しで送るのは Claude の文と固定の質問文だけで、書いてあることは正しい。
- 「次の質問を考えています」が、後半の最後の待ちには合わない。反証役によれば、前の版から同じ場面で同じ表示があり、文言はオーナーの確認待ちのマーカーの下にある。

## つまずいたことと教訓
- **Windows で `wrangler dev` を止めても、Workers のプロセスが残った。** 監査役なしの Workers を、裏で動かしたコマンドごと止めてから、監査役ありで起動し直した。新しい Workers も「Ready on http://127.0.0.1:8787」と出した。しかし、比較の「後」の18回には古い Workers が答えた。結果の `auditCalls` が0だったことで気づいた。プロセスの一覧では、古い `wrangler.js dev ... DEV_AUDIT` の親子が残っていた。すべての Workers のプロセスを止め、ポートで待ち受けるものが無いことを確かめてから起動し直した。1件だけ送り、監査役が呼ばれたことを確かめてから18件を流した。この1回分（約 $0.12）は、記録に使っていない。
  - 次に同じ場面では：設定を変えて Workers を起動し直すときは、止めた後にポートとプロセスが空になったことを確かめる。比較実験は、まず1件だけ送り、変えた設定が効いていることを結果の値で確かめてから全件を流す。
- **緊急のときに、使われない文を確かめていた。** 監査役を入れる場所だけを見て、画面がその文をいつ使うかを見ていなかった。
  - 次に同じ場面では：Workers で文に手を加える処理を足すときは、画面がその文を使う場面（緊急の中断、半分の最後、固定の進行）を `training.ts` で確かめる。緊急の案内を遅らせる処理は入れない。
- **試験計画の状態の行だけを直した。** 各行の結果の欄を見ずに、状態の行に ID を足した。
  - 次に同じ場面では：状態の行を変えるときは、同じ ID の行も同時に直す。

## 確かめたこと
- 単体試験：`npm --prefix web test` で 297/297 PASS。型の検査も通った（2026-11-04、Windows 11、Node.js 26.13、Vitest 5.1）。
- 本物の API での比較（2026-11-04、聞き取り係 Opus 5.5・effort low、監査役 Haiku 5.5、手元の `wrangler dev`）：比較実験の18件を、監査役なしと監査役ありで1回ずつ流した。値は docs/evidence.md「監査役を入れる前と後」を正とする。緊急のときも監査役を呼んでいた版で測った。直した後は測り直していない。
- 画面（2026-11-04、Claude desktop のブラウザ画面、幅375px）：Workers を動かさず、ページの中で `/api/turn` の返事を止めた状態で、1問目に答えた。光と点の動きが出て、読み上げの領域（`role="status"`）は話し手の名前と文だけだった。動きを減らす設定は、ブラウザで切り替えていない。CSS の決まり（すべての動きを止める）と、動きを止めたときに光と点の不透明度が1のままであることを確かめた。

## 推測
- 監査役が本物の出力で文を止める割合は、この18件では0件で分からない。比較実験の文はどれも出してよい文だったため。止める場面は、監査役の比較実験（30件）と単体試験でしか確かめていない。

## 残ること
- オーナーの確認（ADR-0030 と `content.ts` のマーカー）：監査役のモデル、待ち時間、考え中の文言と動き。監査役のプロンプトと実験の期待の値も確認待ち。
- 回答の上限を10回にする：Issue #41。
- 思い出せないときの固定文のマーカーの解除：決定の行は main に入った。Issue は無い。
