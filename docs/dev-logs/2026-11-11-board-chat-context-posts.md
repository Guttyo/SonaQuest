# 掲示板チャットでエージェントへ送る書き込みを Worker でも確かめる

- 日付：2026-11-11
- 対象：Issue #293 の一部（主なコミット bf8db26）
- 関係する ADR：ADR-0047（ボードの掲示板チャット）、ADR-0007（ログ）

## 背景

2026-11-11 のコードの静的な評価で、ボードの掲示板チャット（B-07）について 6 件の指摘が出て、Issue #293 にまとまった。指摘は大きく2つに分かれる。

- エージェントが作った文を画面に出す前の検査（`chatTextProblem`）の穴：見えない文字、ほかの文字体系、電話番号・敬称の型の書き方しだいで通る（指摘 1〜3）
- 画面からエージェントへ送る書き込みの扱い：本文をプロンプトの行にそのまま埋め込んでいる、画面の申告（`by`）をそのまま信じている、セッションと役を照合していない（指摘 4・5）

Issue には、オーナーの判断が要る点が 7 つ挙がっている。検査の語の追加、型の広げ方、使ってよい文字での絞り込み（指摘 1〜3 の直し方）、残る穴の受け入れ、画面の知らせの文言、署名の案、セッションを消すか、の 7 つ。この作業では、判断に回していない構造の直しだけを入れた。

## やったこと

- `web/worker/boardChat.ts` の `buildTurnMessage`：書き込みの本文を `JSON.stringify` した値で1行に入れる。訓練の `prompt.ts` と同じやり方。L154 の説明（「画面から文そのものは受け取らない」）は実際と違っていたので、直した
- `web/src/board/chat/contract.ts` の `parseContextPost`：改行のほかの制御文字を含む書き込みを拒む。範囲は、文字起こしの入口（`web/src/board/karte/transcript.ts` の `CONTROL_CHARS`）と同じにした。改行は拒まない（JSON の値になるので、枠を崩さない）
- `web/src/board/chat/controller.ts`：`sendHuman` は、書き込む前に制御文字を空白に置き換える。`run` は、送る書き込みの制御文字も空白に置き換える
- `web/worker/boardChat.ts` の `screenContextPosts`：`by: "agent"`・`"fixed"` の書き込みに `chatTextProblem` をもう一度当て、通らないものは送らない。`by: "human"` の書き込みには個人の情報・外への誘導の形だけを当て、当たったものは `MASKED_HUMAN_POST` に置き換えて送る。どちらの場合も turn は 400 にしない。ログには種類と件数だけを出す
- `web/worker/boardChatChecks.ts`：`CHAT_FORBIDDEN_PATTERNS` を、中身と並びを変えずに `CHAT_MEDICAL_PATTERNS` と `CHAT_PERSONAL_PATTERNS` に分けた。決定の行（Issue #207）はそのまま残した

## つまずいたことと教訓

- **入口で拒むと、画面のチャットが止まる。** `parseContextPost` で制御文字を拒むだけだと、人がタブを含む文を貼り付けたとき、その欄の turn がずっと 400 になる。今の `controller.ts` は、turn が1回失敗すると固定の掲示に切り替わったまま戻らない。Issue にこの注意が書いてあったので、`sendHuman` での置き換えを一緒に入れた。そのうえで、エージェントの文に制御文字が混じったときにも同じことが起きると分かった（Worker の検査は制御文字を止めない）。`run` で送る書き込みも置き換えることにした。次に入口で何かを拒むときは、画面がその値を作る経路をすべて挙げ、失敗したときに画面がどうなるかを先に見る。
- **申告を確かめ直すなら、正しい申告が通ることを先に確かめる。** `by: "fixed"` に `chatTextProblem` を当てる前に、`CHAT_FIXED` の各ひな形と開始時の掲示が検査を通るかを、件数が null のときと上限のときを含めて試験にした。通らないものがあれば、正しい固定の掲示がエージェントに届かなくなるところだった。
- **Bash の heredoc を通した Python での書き換えで、`\\u0000` が実際の制御文字になった。** `contract.ts` に NUL などの生の文字が入り、`git diff` が「Binary files differ」と出て気づいた。正規表現の `\u` のような逆斜線を含む書き換えは、Edit で行うか、書いた後に `git diff` で文字を確かめる。

## 確かめたこと

2026-11-11、Windows 11。

- `npx tsc --noEmit`：エラーなし
- `npx vitest run --maxWorkers=2`：60 ファイル、1134 件すべて PASS
- 足した試験：`web/worker/boardChat.test.ts`（JSON の値で1行に入れ、見出しの行が変わらない。制御文字で 400、改行だけは 200。agent・fixed の再検査で送らず 200。人の書き込みの置き換えで 200。ログは件数だけ）、`web/worker/boardChatChecks.test.ts`（一覧を分けた後の中身、人の書き込みに当てる型、固定の掲示が検査を通る）、`web/src/board/chat/controller.test.ts`（タブを空白に置き換えて live のまま続く、エージェントの文の制御文字も置き換えて送る）

本物の Managed Agents と画面では確かめていない。

## 推測

- 人の書き込みを置き換えると、エージェントは「（検査で省いた書き込み）」に返事をすることになる。返事の質への影響は、本物で確かめていない。
- 漢字 1〜4 字＋「さん」の型は、「担当さん」のような役割の呼び方にも当たる。人の書き込みでは、エージェントへの文が置き換わるだけで、画面の書き込みはそのまま残る。

## 残ること

- Issue #293 のオーナーの判断の 7 点（文言、検査の語、型の広げ方と使ってよい文字での絞り込み、残る穴、知らせの文言、署名の案、セッションを消すか）
- 画面で人の書き込みを止めて知らせること（知らせの文言はオーナーが決める）
- セッションと役の照合は、Issue #294 の指摘 4 と同じ。そちらで扱う
