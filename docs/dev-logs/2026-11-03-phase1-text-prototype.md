## つまずいたことと教訓
- **試作版で、完成版の送信の説明をそのまま出した**：完成版の文面（`INTRO_LEAD`。入力を Anthropic へ送信すると説明する）と、試作版の注意（`PROTOTYPE_NOTICE`。どこにも送信しないと説明する）を同じ画面に並べ、Copilot に2件指摘された（`content.ts` 18行、`Intro.tsx` 20行）。次に、実際の動作と違う説明があるときは、注意を足すのではなく表示を切り替える（3f84f79 で `content.ts` に `AI_CONNECTED` を置き、試作版では送信しない版の文面だけを出すようにした）。
- **制約に合わせて質問を作り、不自然になった**：ADR-0009 の「実際の薬の名前は質問しない」に合わせて、在りかと手段だけを聞く質問にしたため、実際の聞き取りと順番も中身も違った。次に、制約に合わせて画面の文言を作る前に、実際の手引きの聞き取りの流れを確かめ、制約が体験を損なうならオーナーに諮る（ADR-0021）。
- **入力の扱いを変えたとき、関係する未決の判断を残した**：質問で薬の名前を聞くようにした（b1dd4a1）が、実際の服薬情報の入力を許すかは ADR-0009 のマーカーで未決のままだった。初回画面の「実際の患者情報は入力しないでください」と食い違い、Copilot に指摘された（`content.ts` 27行）。次に、入力の扱いを変える決定をするときは、関係する未決の判断も同時にオーナーに諮る。
- **ADR を前のADRの途中に差し込んだ**：ADR-0021 を ADR-0020 の「影響」の行の直後に足したため、ADR-0020 のマーカーとオーナーの承認の行が ADR-0021 の下にずれた。セッションの中のレビューで見つかり、b1dd4a1 のコミットの前に直した（履歴には残っていない）。次に、ADR は節の末尾に足し、足した後に前のADRの最後の行を確かめる。
- **同じ作業フォルダが別のブランチに切り替わった**：586240f をコミットした後、main を取り込む前に、作業フォルダが `docs/9-dev-logs` に切り替わっていた（根拠はローカルの reflog で、コミットの履歴には無い。`docs/KEEP-THINKING.md` の Issue #9 の節にも、ブランチを切り替えた経緯がある）。PR #10 の衝突は、そのフォルダでブランチを切り替えずに、別の worktree で解いた（9c91271）。次に、同じフォルダで2つのセッションが git を操作しない。必要なら worktree を使う。
- **hook が、件数を数えるだけのシェルのループを止めた**：9c91271 の取り込みを確かめるとき、マーカーの件数を親ごとに数えるループを `.claude/hooks/protect_todo_owner.py` が書き換えと見なして止めた（履歴には残っていない）。次に、マーカーを含むファイルを調べるコマンドはループを使わずに分ける。hook の誤検出そのものは、`.claude/rules/github.md` のとおり別のIssueで扱う。
