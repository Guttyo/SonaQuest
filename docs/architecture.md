# 構成（案）

状態：設計段階。画面（web/）の試作版はあるが、Workers と Claude 連携はまだない。確定事項は docs/decisions.md を正とする。

```
[ウェブブラウザ]  React + TypeScript (Vite)
   │  文字 / 音声認識の結果（Web Speech API。ADR-0004）。読み上げは ElevenLabs、失敗したらブラウザの読み上げ（ADR-0005）
   ▼ HTTPS
[Cloudflare Workers + Hono]  ← secrets: ANTHROPIC_API_KEY、ELEVENLABS_API_KEY
   ├─ /api/turn    1ターン分の判定と次の手を返す。Claudeの出力を検証してから返す（ADR-0015）
   ├─ 読み上げの中継  読み上げる文だけを ElevenLabs へ送る（利用者の回答は送らない。ADR-0005）
   └─ 保存なし。公開する版では本文のログ出力なし（開発中だけの出力は ADR-0007 の追記）
   ▼
[Claude API]
```

## 状態の持ち方
- 会話の状態はブラウザのメモリにだけ持つ。Workersは毎回、必要な分を受け取って返すだけ（状態を持たない）。
- ブラウザの永続ストレージに保存しない。API失敗時も、メモリ上の回答と進行は失わない。
- 結果画面の「利用者の回答」は、ブラウザのメモリに保持した入力そのものから表示する。Claudeの応答から原文を復元しない（ADR-0009）。

## 進行のうち、Claudeを使わずに決める部分
- 想定外の出来事：本人がタップで確かめた一番の情報源からルールで選ぶ（ADR-0016、ADR-0019）。確認のタップは回答の回数に数えない
- 緊急時の中断：「訓練をやめる」ボタンと語の照合（ADR-0011）
- 準備行動の並び順：判定が「確認していない」「未確認と気づいた」の観点に関係するものを上にする
- 固定の6問による進行（ADR-0012）
- 前半から後半への切り替えと、後半の最初の立て直しの問い（固定文。ADR-0019）

## /api/turn の入出力（案）
入力：これまでの回答（最大6件）、現在のターン番号、出来事が起きた後はその出来事のID（どの情報源が使えなくなったか。観点②の判定に使う。ADR-0019）。訓練に必要な範囲に限り、それ以外は送らない
出力（Claudeに構造化出力で返させ、Workersで検証する）：
```json
{
  "emergency": false,
  "viewpoints": {
    "location": "confirmed | aware_unconfirmed | not_mentioned",
    "alternative": "...", "current": "...", "unrecorded": "...", "proxy": "..."
  },
  "next": {"type": "ask | clarify | finish", "question_id": "q3"}
}
```
- 検証（ADR-0015）：スキーマ、許可した値だけか、文字列の長さの上限、余分なキーの拒否。失敗したら固定の進行へ。
- 公開前の必須条件（ADR-0003）：回数制限、入力の大きさの上限（上限を超えたらClaudeを呼ばずに拒否）、Claude APIの支出の上限。
- 画面に出す質問文・聞き返し文：Claude が作ってよいのは質問文、受け止めの一言、質問し直す文だけで、Workers で長さ・禁止表現・利用者の発言の繰り返しを検査し、通らなければ ID から固定文を引く（ADR-0025）。
- `emergency` は補助。中断は語の照合でも行う。

## 安全の層
1. 画面：常に「訓練をやめる」ボタン。初回画面でAnthropicへの送信を明示し、氏名・住所・電話番号・実際の患者情報を入れないよう案内（架空の薬の情報でも練習できる）
2. プロンプト：しないこと（薬の名前の修正、薬効の評価、正誤の判定、服薬の適否の判断、診断、薬の名前の有無による個別の医療判断）を明記し、出力を構造化データに限る。薬の名前・量・病名は質問してよいが、答えを評価しない（ADR-0021）
3. サーバー側の検証：形式と値の検証。Claude が作った文は禁止表現と繰り返しの検査（ADR-0025）
4. 結果画面：利用者の回答は端末内の入力から原文表示、判定は観点ごとの3段階だけ。「確認できた」は内容の正確さを保証しないと明記
