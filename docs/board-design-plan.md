# 地域本部の医薬品ボード：デザインの見直しの計画書（Issue #143、B-11）

この文書は Issue #143 の第1段（計画）。**コードはまだ変えていない**。オーナーがこの計画を確認してから、第2段（実装）に入る。実装は Issue #141（B-09：ログイン・権限・カルテの確認状態）のマージの後に重ねる（7章）。

- 対象：`web/src/screens/Board.tsx`、`web/src/board/board.css`、`web/src/screens/BoardMap.tsx`、`web/src/board/chat/chat.css`、`web/src/board/PatientArrivals.tsx`
- 主な画面：タブレットの横向き（1180×820、1024×768）。指で操作する。スマホ幅（640px 以下）は今の選択式を保つ
- 使う人と場面：避難所の本部で、忙しい人が立ったまま一目で見る。何人かで1つの画面をのぞき込む
- 目標：**目を細めて見ても、注意が要るところだけが浮く**（ISA-101 のハイパフォーマンス HMI の考え方。平常は無彩色、色は異常だけ）
- 決める点の一覧は 9章。決まるまでは、この文書の色・数値・文言は Claude Code の下書き

## 1. 今の画面の問題

### 1.1 見た目の型（生成された UI によくある形）
1. **左の太い色線**。左の拠点の一覧は、1件ずつ左に 5px の線のある箱（`board.css` 1142 行 `.board-pane-item`、選ぶと 2014 行で青緑の線）。発注の提案も左に 5px の橙の線（1405 行 `.board-order`、承認済みは緑の線）。最終報告が古い救護所は左の線が黄になる（1998 行）。
2. **同じ角丸と影の箱の繰り返し**。指標の札、表の枠、拠点の一覧、救護所の数字、発注の提案、カルテ、地図の凡例が、どれも「白い面＋1px の線＋角丸」の箱。角丸は 12px が約 20 か所、後から 6px で上書きしている所もあり（1890 行から）、値がそろっていない。札の形は 999px の丸い札（11 行、102 行、1179 行、1231 行）。
3. **箱の中に箱**。救護所の詳細では「今日の様子」の7つの数字がそれぞれ箱になり、その中にさらに「薬剤師 1人不足」の札の箱がある（画像 board-143-before-1024-site）。
4. **同じ大きさの数字が並び、どれが大事か分からない**。救護所の詳細で「在庫切れ 0」も「避難者数 300 人」も同じ大きさ・同じ箱。0 は「問題なし」なのに、問題のある数字と同じ強さで目に入る。

### 1.2 色の使い方
5. **色がどの箱にも同じ強さで付いていて、注意が要るところが浮かない**。左の一覧では救護所4か所のうち3か所に黄の線と黄の札が付く（D・B は「12時間以上 報告なし」と「記録の未着・転記待ち」の両方が黄）。黄が多すぎて、本当に止まっている救護所C の「在庫切れ 1」（赤）が埋もれる。
6. **同じ黄が別の意味で使われている**。「報告が古い」「記録の未着・転記待ち」「承認待ちの提案」「在庫切れ見込み」が、すべて同じ黄の札。
7. **選んでいることと注意を、同じ基本色（青緑 `#1d6f86`）で示している**。選んだ拠点の左線と背景、今のタブの下線、指標の札のうち重要な2つの太い枠（1959 行 `.board-tile-lead` など）、リンクの文字、デモの実行中の印が、すべて青緑。「どれを見るべきか」と「今どこを見ているか」が区別できない。
8. **正常にも色が付いている**。緑は「余裕あり」「通行可」「オンライン」「承認済み」に付く（`.board-pill.ok`、`.board-heat .cell.ok`）。ISA-101 の考えでは、正常は色を付けない。
9. **地図とグラフが多色**。地図の地は、ベージュ・水色・茶・薄い緑など、建物や水路ごとに色が違う（`BoardMap.tsx` 89〜124 行、185〜208 行）。推移のグラフは救護所ごとに4色（`Board.tsx` 101 行 `SITE_COLORS`）。注意の赤と黄が、地の色に混ざって弱く見える。

### 1.3 文字と配置
10. **文字が小さい**。表・注記・札は `--fs-sub` 14px、`--fs-caption` 13px（`board.css` 70 行、86 行）。立って少し離れて見るには小さい。本文 16px 以上の方針に合わない。
11. **大事でない行が上にある**。タブの下の「前回から変わったこと」の行は、ほとんどの時間「更新はありません」と出るだけで、一番目立つ位置の1行を使っている。
12. **指標の札が折り返す**。1180 幅では5つの札が4つと1つに、1024 幅では3つと2つに割れる（画像 board-143-before-1180-hq、board-143-before-1024-hq）。割れた札の1つ（報告が古い救護所）だけが黄の面で2段目に浮き、ほかの重要な札より目立つ。
13. **上の帯に情報が少なく、操作が多い**。題「SonaQuest」と副題、丸い札「架空データ」、集計時点、「はじめにへ戻る」「デモ操作」の2つの枠付きボタン。災害名・ログイン中の救護所と担当者（Issue #141）が置ける場所がない。帯としての決まった形（高さ・並び）がなく、項目が増えると折り返す。
14. **タップできる所が 44px に足りない**。ヘッダーのボタン 40px（1904 行、1914 行）、デモの操作 36px（1936 行）、リンク 32px（2104 行）、「画面の見方」32px（2148 行）。

## 2. 色（6個）

ISA-101 の考え方：平常の画面は無彩色のグレーで描き、色は「放っておくと止まるもの」「人が確かめるまで先に進めないもの」だけに使う。色の数を減らすほど、色の付いた所が浮く。

### 2.1 使う色
値は Claude Code が自分で選んだ下書き（赤は今の `board.css` 1520〜1522 行の `--board-bad` の値をそのまま使う。灰と黄は新しく選んだ）。コントラスト比は白（`#ffffff`）の上での概算で、実装のときに測り直して `docs/STATUS.md` に記録する。

| 名前（CSS 変数） | 値 | 使う所 | 白の上のコントラスト（概算） |
|---|---|---|---|
| 地 `--b-ground` | `#ededed` | 画面の地。帯の下の全体 | 文字には使わない |
| 面 `--b-surface` | `#ffffff` | 表と一覧の面 | 文字には使わない |
| 線 `--b-rule` | `#c8c8c8` | 表の罫線、列の区切り | 文字には使わない |
| 墨 `--b-ink` | `#222222` | 本文、数字、選んだ所（反転の地） | 約 16：1 |
| 灰 `--b-ink-soft` | `#555555` | 見出しの小さな文字、補足、「なし」 | 約 7.5：1 |
| 赤 `--b-stop` | 記号と枠 `#b42318`、文字 `#a31d14`、面 `#fdeceb` | 止まっている（下の表） | 文字 約 7.7：1（薄い赤の面の上で 約 6.7：1） |
| 黄 `--b-check` | 面 `#f2c230`、文字は墨 `#222222` | 確かめる（下の表） | 黄の面の上の墨の文字 約 9.5：1 |

表は7行だが、地・面・線・墨・灰は同じ無彩色の明るさ違いなので、色相は**無彩色・赤・黄の3つだけ**になる。色の数は「無彩色4段＋赤＋黄」の6個と数える（面と地は明るさ違いの1組）。

- 黄は、文字の色にしない（白の上の黄の文字は読めない）。黄は**面と記号の地**にだけ使い、上に墨の文字を置く。
- 赤は、文字と記号に使い、面は薄い赤 `#fdeceb` にとどめる。赤の大きな面は作らない（何人かで見たときに、赤い面が画面を占めると、どこが赤いのかが分からなくなる）。
- 青緑（今の基本色 `#1d6f86`）と緑は使わない。

### 2.2 どの状態にどの色を使うか

| 区分 | 状態 | 色 | 記号 | 文字 |
|---|---|---|---|---|
| 止まっている | 在庫切れ（現地 0） | 赤 | 塗りの四角に白抜きの × | 「在庫切れ」 |
| 止まっている | 未交付あり（渡せなかった薬がある） | 赤 | 同上 | 「未交付あり」 |
| 止まっている | 監査で止めた（Issue #142 の監査の指摘。名前は #142 のマージ後に合わせる） | 赤 | 同上 | #142 の文言 |
| 確かめる | 在庫切れの見込み（目安の日数より早く切れる） | 黄 | 黄の三角に墨の ! | 「切れる見込み」 |
| 確かめる | 在庫が未確認 | 黄 | 同上 | 「未確認」 |
| 確かめる | 最終報告が古い（今は仮に 12 時間以上） | 黄 | 同上 | 「12時間以上 報告なし」 |
| 確かめる | カルテの確認待ち（Issue #141 の確認状態。名前は #141 のマージ後に合わせる） | 黄 | 同上 | #141 の文言 |
| 確かめる | 承認待ちの発注の提案 | 黄 | 同上 | 「承認待ち」 |
| 確かめる | 通行止め・迂回（地図と経路） | 通行止めは赤、迂回は黄 | 地図の上は線の形（通行止めは × の印、迂回は破線） | 「通行止め」「迂回」 |
| 平常 | 余裕あり、通行可、オンライン、承認済み、確認済み | **色なし**（墨か灰の文字） | なし | 文字だけ |
| 平常 | 記録の未着・転記待ちの件数 | **色なし**（数を墨の太字で出す） | なし | 「未着 97・転記待ち 6」ではなく列の見出しと数で示す |
| 平常 | 薬剤師の不足 | **色なし**（灰の枠の札。目立たせ方は今と同じで、形は四角） | なし | 「薬剤師 1人不足」 |
| 選んでいる所 | 選んだ拠点、今のタブ | **色なし**（墨の地に白の文字、または墨の 3px の下線） | なし | 拠点名・タブ名 |
| 操作 | ボタン、リンク | **色なし**（主なボタンは墨の地に白、ほかは墨の枠。リンクは墨の文字に下線） | なし | ボタンの文言 |

決め方の考え：

- **件数があるだけでは色を付けない**。記録の未着・転記待ちは、どの救護所にもふつうにある数で、色を付けると4か所すべてが黄になる（1.2 の問題5）。数は列にそろえて墨で出し、見比べられるようにする。
- **色は2段階だけ**。赤は「止まっている（今すぐ手配）」、黄は「人が確かめる」。3段階目（橙など）は足さない。ISA-101 では優先度を色の数で増やさず、記号と並び順で示す。
- **状態は色だけで示さない**。必ず記号（形が違う：四角と三角）と文字を添える。色の見分けが難しい人と、白黒の印刷・日差しの強い屋外で見たときにも、形と文字で分かる。
- **薬剤師の不足**は、2026-11-05 のオーナー決定（赤にしない、職種を残し、ほかの印と同じ目立たせ方）に合わせ、今の灰の枠の札の目立たせ方のままにする（形は丸から四角に変える）。
- **緑を外す**のは、Issue #107 の色の点検の決まり（`board.css` 1518 行：赤・黄・緑は状態だけに使う）を変えることになる。9章でオーナーに決めてもらう。

### 2.3 地図とグラフ
- 地図の地（建物・水路・公園・道）は、すべて灰の明るさ違いにする（地 `#ededed`、建物 `#e0e0e0`、水路 `#d4d4d4` に細い斜線、道は白）。名前の文字は灰。
- 地図の上の色は、救護所の状態（赤・黄）と通行止め・迂回だけ。今の「黄でゆっくり光る」「破線が流れる」（ADR-0049）は残す。動きを減らす設定で止めることも今のまま。
- 推移のグラフ（`SITE_COLORS` の4色）は、全部の線を灰にし、選んだ救護所の線だけを墨で太くする。線の端に救護所名を直接書く（凡例の色に頼らない）。

### 2.4 目を細めたときの確かめ方
実装の後、1180×820 のスクリーンショットをぼかして（ブラウザの開発ツールで `filter: blur(6px)` を一時的にかける。コードには入れない）、浮いて見えるのが赤と黄の所だけかを確かめる（8章）。

## 3. 書体

- **ゴシックで統一**（ADR-0037、Issue #71）。`--font-gothic`（端末に入っているゴシックだけ）をそのまま使う。外部のフォントは使わない。
- **数字はすべて tabular-nums**（`font-variant-numeric: tabular-nums`）。列の数字は右にそろえる。
- **太さは 400 と 700 の2段階**（ADR-0037 の決定4）。

### 3.1 大きさの段階（ボードの中だけ）

| 段 | 大きさ | 太さ | 行間 | 使う所 |
|---|---|---|---|---|
| 大きい数 | 32px（2rem） | 700 | 1.1 | 本部の数字の列（不足が出ている救護所など5つ） |
| 救護所名 | 20px（1.25rem） | 700 | 1.3 | 右の詳細の題、左の一覧の名前は 18px |
| 見出し | 18px（1.125rem） | 700 | 1.4 | 表の題（確認・手配が必要な事項など） |
| 本文 | 16px（1rem） | 400 | 1.6 | 表の中身、一覧の中身、ボタン |
| 列の見出し・補足 | 14px（0.875rem） | 700（列の見出し）、400（補足） | 1.45 | 表の列の見出し、注記、「画面の見方」の中 |

- **表の中身は 16px**（今は 14px）。14px は列の見出しと注記だけにし、13px（`--fs-caption`）はボードでは使わない。
- 本文 16px 以上を守ると、1024 幅で表の列が収まらなくなる。4章の「1024 幅で削る列」で対応する。
- 見出しは英大文字の小見出しにしない（日本語だけ）。

## 4. レイアウト

### 4.1 方針
- **上に固定の帯**（56px）、**左に救護所の一覧**、**右に選んだ拠点の詳細**。カードより行と表。
- 箱は「表」と「一覧」の2種類だけ。表は1枚の白い面に罫線で行を分ける。箱の中に箱を作らない。
- 角丸は 0 か 4px（ボタンと記号だけ 4px）。影は使わない。
- タップできる所は高さ 44px 以上（一覧の行、タブ、ボタン、リンクの行全体）。

### 4.2 1180×820（タブレットの横向き）


- 左の一覧は表の形。列は「拠点」「在庫の注意」「確認待ちのカルテ」。最終報告の時刻は名前の下の2行目に灰で出し、古いときだけ黄の記号と文字にする。
- 「在庫の注意」の列は、在庫切れがあれば赤の記号と件数、無くて見込み・未確認があれば黄の記号と件数、どちらも無ければ灰で「なし」。
- 「確認待ちのカルテ」は Issue #141 が作る確認状態の件数。#141 のマージ前は「記録の未着・転記待ち」の件数を墨で出す（色なし）。
- 選んだ行は、墨の地に白の文字（反転）。色は使わない。
- 本部の数字は、箱を5つ並べるのをやめ、**1行の表**（列を細い縦の罫線で区切る）にする。注意が要る数字（不足が出ている救護所 > 0、在庫切れ > 0、報告が古い > 0）だけ、数字の左に赤か黄の記号を付ける。0 のときは灰で「0」。
- 「前回から変わったこと」は、更新があるときだけ、数字の列の上に1行で出す。更新が無いときは出さない（今の「更新はありません」の行をやめる。読み上げには今の文を残す）。

### 4.4 1024×768

## 5. 原則

### 5.1 使わないもの
- 左の太い色線（箱の左だけに付ける色の線）
- すべて同じ角丸と影の箱の繰り返し。箱の中の箱
- グラデーション（地図の凡例の破線の見本 `repeating-linear-gradient` は、線の形を描くためのもので飾りではないので残す）
- 英大文字の小見出し（「OVERVIEW」「STATUS」など）
- 中黒でつないだメタ情報（「東地区・最終報告 2時間前・薬剤師 1人」のような1行）。列か2行目に分ける
- ボタンの文言の矢印（「開く →」など）
- 読み込み時のふわっと出る動き（フェード・スライドの入り）。地図の光と流れ（ADR-0049）は状態を示す動きなので残し、動きを減らす設定で止める
- 999px の丸い札。札は四角（角丸 4px 以下）
- 正常の緑、選んだ所の色付きの背景、色だけの印

## 6. デジタル庁デザインシステムのトークン

`@digital-go-jp/design-tokens`（2026-11-06 に `npm view` で確かめた版は 2.1.0、MIT、著作権者はデジタル庁）。中身は CSS 変数・JS の値（`dist/tokens.css`、`tokens.js` など）で、色（`--color-primitive-*`、`--color-neutral-solid-gray-*`、`--color-semantic-error-1` など）、文字の大きさ（`--font-size-16` など）、角丸（`--border-radius-4` など）がある。書体の変数は `--font-family-sans: 'Noto Sans JP', sans-serif`。

| | A：トークンを使う（依存を足す） | B：使わない（CSS 変数を自前で持つ） |
|---|---|---|
| 中身 | `web/package.json` に依存を足し、`tokens.css` を読み込んで、ボードの変数（2.1 の `--b-*`）をトークンに向ける | `board.css` の先頭に `--b-*` を自前の値で書く |
| 良い点 | 灰の段階と赤・黄の値が、公的なデザインシステムの値に乗る。審査や説明で「土台」を言える | 依存が増えない。値を1か所で直せる。凍結までの手間が少ない |
| 気を付ける点 | 依存の追加はオーナーの承認が要る（CLAUDE.md 絶対ルール7）。README にライセンス表記（MIT、デジタル庁）を入れる。`tokens.css` は `:root` に全部の変数（数百）を置くので、使う変数だけを参照する。**`--font-family-sans` は Noto Sans JP を指すので使わない**（ADR-0037：端末のゴシックだけ、外部のフォントは使わない）。Figma・ガイドライン本体は使わない | 値は自分で決める。**トークンの値を手で写して自前の CSS に置くことはしない**（CLAUDE.md 絶対ルール1：他のリポジトリのデータを複製しない。使うなら依存として入れ、ライセンスを表記する） |
| 影響 | `web/package.json`、`package-lock.json`、`README.md`、`board.css` | `board.css` だけ |

**推奨：B（自前の CSS 変数）**。理由は3つ。

1. 使う色は無彩色4段と赤・黄の6個だけで、トークンの数百の変数のうち使うのは数個になる。依存を足す得が小さい。
2. 実装は Issue #141 のマージの後になり、機能凍結までの残りが短い。依存の承認とライセンス表記の手順を増やさない方が、見直しと撮影に時間を使える。
3. 書体の変数は使えない（ADR-0037）ので、トークンの「文字」の部分は乗らない。

2.1 の値は Claude Code が自分で選んだ下書き（赤はこのリポジトリの今の `--board-bad` の値）で、トークンの値を写したものではない。オーナーが A を選んだときは、2.1 の変数をトークンの変数（灰の段階、`--color-semantic-error-1` など）に向け直し、近い値に置き換える。

## 7. 実装の手順

### 7.1 Issue #141 との重ね方
- Issue #141（B-09）は `Board.tsx` に、ログイン・権限・カルテの確認状態・アクセス記録を足す。同じファイルの同じ部位（帯、一覧、カルテの一覧）を変える。
- **#141 のマージの後に、この Issue のブランチを main から作り直して実装する**。#141 の作業中には `Board.tsx` を変えない。
- Issue #142（抽出型要約と Managed Agents の監査）が監査の指摘を画面に出すなら、その状態にも 2.2 の赤を当てる。#142 が先にマージされたらその文言に、後なら #142 の側で 2.2 に合わせる。

### 7.2 手順（第2段）
1. main を最新にし（`git pull --ff-only`）、#141 が入っていることを確かめてから作業ブランチを作る。
2. `board.css` の先頭に `--b-*` の変数（2.1）を足し、今の `--board-accent` などの上書き（1519 行、1879 行あたり）を変数に置き換える。青緑と緑の参照を消す。
3. 帯（`board-head`）を固定の帯にし、#141 のログインの表示を入れる。
4. 左の一覧（`board-pane`）を表の形に作り直す（列：拠点・在庫の注意・確認待ち）。左の太い線、箱、丸い札を消す。
5. 本部の数字（`board-kpi-row`）を1行の表にし、「前回から変わったこと」を更新があるときだけ出す。
6. 確認・手配が必要な事項、発注の提案、救護所の詳細の数字、在庫の表、カルテの一覧を行の表に直す。状態の記号（四角の ×、三角の !）を小さな SVG の部品で作る（`aria-hidden`、文字を必ず並べる）。
7. 地図の地とグラフの色を灰に（2.3）。`chat.css`、`PatientArrivals` の色を変数に。
8. 文字の段階（3.1）を当て、1024 幅で削る列（4.4）を入れる。タップの所を 44px に。
9. 本部の在庫タブに、国の医薬品供給状況への外部リンクを置く（4.6）。定数を `text.ts` に足し、README と `docs/references.md` に出典と確認日を書く。
10. 試験：今の試験（`npm --prefix web test`）が通ること。`data-testid` と読み上げの名前は変えない。状態の記号に文字が並んでいることを確かめる試験を足す。外部リンクが本部の在庫タブにだけ出ること、表示名・URL・添える文・`target="_blank"`・`rel="noopener noreferrer"` が合っていることを確かめる試験を足す。

### 7.3 変えないもの
- 架空データ、デモの reducer（`demo.ts`）、算数（在庫・日数・提案の数量）、文言（`text.ts` の固定文）、試験で使う `data-testid`
